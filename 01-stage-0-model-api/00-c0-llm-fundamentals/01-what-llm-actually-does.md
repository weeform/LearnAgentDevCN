# C0-1 · 大模型到底在做什么
## 1. 一句话答案

如果只用一句话概括大模型，那就是：

> **它是一个函数，输入一串 token id，输出"下一个 token 的概率分布"。**

写成你看得懂的签名：

```python
def model(tokens: list[int]) -> list[float]:
    """
    输入：一串整数，每个整数是词表里的一个编号
    输出：一个长度等于词表大小（通常 3 万到 20 万）的浮点数组，
          每个位置是"下一个 token 是这个编号"的概率
    """
```

调用一次，得到的是**一个 token 的候选概率**，不是一整段回答。

那一段完整的回答是怎么来的？**循环调用**：

```
tokens = ["今天", "天气"]
while not 停止:
    probs = model(tokens)      # 这一次只预测一个
    next  = sample(probs)      # 按概率抽一个
    tokens.append(next)        # 拼回输入
```

这就是所谓**自回归（autoregressive）**——把自己生成的东西再喂回给自己。C1-1 里的第 ⑤ 步就是这个循环。

记住这个循环，后面所有东西都是它的细节。

## 2. 输入是什么：一串整数

模型不认字符串。你发给 API 的 `"今天天气怎么样"`，在进模型之前会被切成若干 token，每个 token 换成词表里的一个整数编号：

```
"今天天气怎么样"  →  ["今天", "天气", "怎么样"]  →  [38102, 5521, 99204]
```

词表（vocabulary）就是一张固定的映射表，本质是个双向 hash map。

这一点有三个立刻能用的推论：

1. **模型对字符不敏感，对 token 敏感**。你熟知的那些"为什么大模型数不清 `strawberry` 里有几个 r"的笑话，根源就在这里。
2. **计费按 token 不按字**。C3 会展开。
3. **上下文长度的单位是 token**。所谓"128K 上下文"，是 128K 个 token，不是 128K 个字。

## 3. 输出是什么：一个概率分布

输出的数组长度等于词表大小。举例（假设词表只有 5 个词）：

```
token      概率
"很好"      0.42
"不错"      0.23
"很差"      0.11
"。"        0.09
"今天"      0.003
...        （其余几万个词瓜分剩下的概率）
```

这个数组在 Softmax 之前叫**logits**（未归一化的分数），经过 softmax 之后才是概率。C1-2 讲的 `temperature`、`top_p`，改的都是**从这个数组里怎么挑一个**这一步——注意，它们改的不是模型"知道什么"，而是"怎么选"。这个区分在 Agent 开发里非常重要。

## 4. 一个必须破除的误解：它不"理解"

从上面的循环可以看出，模型做的事是：

> 在训练数据的统计规律下，给定这串 token，下一个最可能是什么。

它没有一个"世界模型"，不会在心里推理。我们看到的"推理能力"，是**大规模语料上的模式匹配 + 足够深的网络**涌现出来的效果。

这对 Agent 开发者意味着三件具体的事：

| 误解 | 现实 | 后果 |
|---|---|---|
| 它知道自己不知道什么 | 它不知道。它会自信地编 | 必须靠工具 + prompt 约束事实性 |
| 它能自己在心里算数 | 不能，它只能生成"看起来像计算过程"的文本 | 计算必须交给工具 |
| 它记得之前说过什么 | 不记得。是**你**每次把历史重新发过去 | 上下文管理是你的活，不是它的 |

第三点尤其关键：**API 是无状态的**。模型本身没有任何跨请求的记忆。你感觉它有记忆，是因为你的程序每次都把完整对话历史重新发了一遍。

## 5. 训练与推理：两件完全不同的事

|  | 训练 | 推理 |
|---|---|---|
| 做什么 | 调整模型里的参数 | 用固定的参数做前向计算 |
| 频率 | 一次，几周到几个月，几百万到上亿美元 | 每时每刻，无数次 |
| 数据 | 海量文本，一次性 | 你发的那点输入 |

**训练完之后，参数就冻结了。**推理时模型是一张只读的常量表——这点很重要，它意味着：

- 模型不会因为跟你聊了几天就变聪明（除非厂商更新版本）。
- 所谓"记忆""个性化"，全部要靠**你把信息塞进输入**（上下文工程、RAG），或者厂商微调。
- 推理的成本是纯算力，所以**推理优化极其值钱**——这正是 C2（KV Cache）存在的经济理由。

## 6. "参数"到底是什么

你常听到"7B""671B"，说的是参数量。参数就是一堆浮点矩阵，推理时它们是只读常量。

一个有用的量级直觉：

- **7B 参数 ≈ 70 亿个数字**。以 2 字节（fp16）存，光权重就约 14 GB 显存。
- 这 70 亿个数字被组织成很多层，每层有若干矩阵。**层数**和**每层宽度**是模型的两个核心形状参数，C2-3 算显存时会用到。

至于这些数字怎么来的（反向传播、梯度下降）——**你不需要知道**。就像你写业务代码不需要知道 CPU 怎么造的。

## 7. 这一篇要带走的三个结论

1. 大模型 = 一个"输入 token 序列、输出下一个 token 概率分布"的纯函数；完整回答靠循环生成得来。
2. 它做的是大规模统计模式匹配，不是理解，也不是推理——所以事实性和计算必须外包给工具。
3. 参数是训练后冻结的只读常量，推理是纯计算，因此推理优化极其值钱。
