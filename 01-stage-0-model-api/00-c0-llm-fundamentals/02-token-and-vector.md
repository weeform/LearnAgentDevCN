# C0-2 · Token 与向量：模型只认数字
## 1. 为什么不能直接把字符喂进去

最自然的想法：模型处理文本，那就把字符喂进去呗。三个理由说明为什么不这么做：

1. **序列会爆炸**。按字符算，一段话的长度是按词算的 3-5 倍，而模型的计算量随长度**平方增长**（C0-4 会讲为什么是平方）。
2. **学不到语义**。`c-a-t` 三个字符各自没有意义，但 `cat` 作为一个整体有。
3. **生词无解**。出现训练中没见过的字符组合，模型完全无法处理。

所以需要一个中间单位：**token（子词）**。

## 2. token = 子词，不是字也不是词

token 是"介于字符和词之间"的单元。直觉上：

```
英文 "unbelievable"  →  ["un", "believ", "able"]      # 常见词根被切出来
中文 "今天天气怎么样"  →  ["今天", "天气", "怎么样"]     # 常见词整体成 token
代码 "def calculate"  →  ["def", " calculate"]          # 缩进经常和词粘在一起
```

它是怎么切出来的？主流算法叫**BPE（Byte Pair Encoding）**，做法是：从字符开始，统计语料里哪两个片段最常挨在一起，就把它俩合并成一个新片段，反复进行直到词表达到预定大小。

**你只需要知道这些。分词的细节、中英文差异、算钱时会踩的坑，全在 C3-1，这里不重复。**

这一篇只需要你接受一个结论：**文本进模型前，会被切成一串整数 id。**

## 3. id → 向量：为什么非得变成向量

现在我们有了一串整数，比如 `[38102, 5521, 99204]`。能直接喂给网络吗？不能。

原因很具体：**整数之间没有"距离"这个概念。**

在整数编号里，`38102`（今天）和 `38103`（明天）编号相邻，`5521`（天气）离得很远。但语义上"今天"和"明天"的关系，跟"今天"和"天气"的关系，谁更近？——从编号完全看不出来。编号是任意分配的。

如果直接把 id 当数值用，模型会学到一个荒谬的先验："编号接近的词意思接近"。

解决办法是**embedding（嵌入）**：给词表里每个 id 分配一个**可学习的向量**，通常是几千维。

```python
embedding_table: Tensor[vocab_size, d]   # 一张大表，比如 [100000, 4096]
x = embedding_table[token_id]            # 查表，得到一个 d 维向量
```

这本质就是一次**数组下标查表**。只不过表里存的是向量，而且这张表是训练学出来的。

这么做的好处：向量空间里，"今天"和"明天"的向量会靠得很近（点积大），"今天"和"香蕉"会很远。**语义相似性变成了几何距离**，网络就能做运算了。

> 程序员类比：这跟 word2vec 是一回事，只是这里的表是模型的一部分，跟其他参数一起训出来的。

## 4. 现在序列长什么样

切成 token、查完表之后，你的输入变成了一个**矩阵**：

```
        ← d 维（比如 4096）→
token 1  [ 0.12, -0.33,  0.87, ... ]
token 2  [-0.45,  0.21, -0.09, ... ]
token 3  [ 0.78,  0.05,  0.31, ... ]
    ↑
  N 个 token（序列长度）
```

**N × d 的二维表。**这是接下来所有计算的基本数据结构。

请务必记住这个形状，因为：

- 后面每一层都在**更新这张表里的数字**，形状始终不变。
- 我们常说的"上下文长度"，就是这张表的**行数 N**。
- 我们常说的"模型维度 / hidden size"，就是**列数 d**。

## 5. 一个容易漏掉的问题：位置信息去哪了

注意一个反直觉的事实：**上面这套查表操作，跟 token 在句子里的位置毫无关系。**

"我爱你"和"你爱我"，切出的 token 完全一样，查表得到的向量也完全一样——但意思天差地别。

更麻烦的是，后面 C0-4 要讲的**注意力机制，本质上是个集合运算，它对顺序天然不敏感**（它做的是"两两配对打分再加权求和"，打乱顺序结果不变）。

所以必须**显式地把位置信息注入进去**。做法叫**位置编码（positional encoding）**：给每个位置生成一个表示"我是第几个"的向量，加到对应的 token 向量上。

```
x_i = embedding[token_id_i] + position[i]
```

加完之后，位置 1 的"我"和位置 3 的"我"就不再是同一个向量了。

> 现代模型（RoPE、ALiBi 等）做法各有不同，有的加在向量上、有的加在注意力计算里。**你只需要知道：位置信息是被额外注入的，不是天然存在的。**这一条在判断"为什么某些长上下文方案在外推时会崩"时很有用。

## 6. 另一侧：向量怎么变回 token

模型内部一直在这张 N×d 的表上做运算。要输出下一个 token 时：

1. 取**最后一层、最后一个位置**的那个向量（d 维）。
2. 用它去和"词表 embedding 矩阵"做一次矩阵乘法——相当于拿这个向量去和词表里**每一个词**的向量算相似度。
3. 得到一个长度 = 词表大小（比如 10 万）的分数数组，这就是**logits**。
4. softmax 归一化 → 概率分布 → 采样一个。

```
最后一层最后位置的向量 (d 维)
        ↓   × 词表矩阵转置 [d, vocab_size]
     logits (vocab_size 维)      ← 每个词一个分数
        ↓   softmax
     概率分布
        ↓   sample（temperature / top_p 在这一步起作用，见 C1-2）
     下一个 token id
```

**这就是 C1-1 第 ③ ④ 步的完整底图。**记住它，C1-2 讲采样时你会知道自己在改哪个环节。

## 7. 完整链条

```
字符串
  ↓ 分词（BPE，细节见 C3-1）
token id 序列  [38102, 5521, 99204]
  ↓ 查 embedding 表 + 加位置编码
N × d 的矩阵
  ↓ 过 L 层 Transformer（C0-3 讲一层做了什么）
最后一层、最后一个位置的向量
  ↓ 乘词表矩阵
logits（长度 = 词表大小）
  ↓ softmax
概率分布
  ↓ 采样
下一个 token id  →  拼回序列，回到最上面
```

## 8. 这一篇要带走的结论

1. token 是子词单元；文本进模型前变成一串整数 id。
2. id 必须变成向量，因为整数编号没有语义距离；embedding 就是一张可学习的查表。
3. 此后所有计算都在**N × d 的矩阵**上进行——N 是上下文长度，d 是模型维度。
4. 位置信息是**额外注入**的，注意力本身不看顺序。
5. 输出侧是把最后的向量投影回词表大小，得到 logits。
