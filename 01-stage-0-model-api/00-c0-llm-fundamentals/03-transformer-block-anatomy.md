# C0-3 · Transformer 骨架：一层在做什么
## 1. 先建立一个总体的图

上一节结束时，输入已经变成了一张**N × d 的矩阵**（N 行 token，每行 d 维）。

模型做的事，就是把这张表**反复加工 L 次**（L 是层数，比如 32 层、80 层）。每次加工叫"过一层"。

```
输入矩阵 (N × d)
    ↓
┌─────────────┐
│  第 1 层     │   ┐
└─────────────┘   │
       ↓           │  重复 L 次
┌─────────────┐   │  形状始终 N × d，只有数字在变
│  第 2 层     │   │
└─────────────┘   ┘
       ↓
      ...
    ↓
输出矩阵 (N × d)
    ↓
取最后一行 → 投影回词表 → logits
```

**关键心智模型**：

> 每一行是那个位置 token 的"当前表示（representation）"。每过一层，这些表示就被更新一次，变得**更 contextual（更融合上下文）**。形状永远不变，变的是数字的含义。

## 2. 一层内部：两个子层

一层 Transformer 里面有两个完全不同的子模块，它们分工极其清晰：

### 子层 A：注意力（Attention）—— 横向混合

**干什么**：让每个 token 去看看别的 token，把别人的信息揉进自己这一行。

```
token 1  ┐
token 2  ├─→ 互相"看"一遍，各自更新 ─→ 更新后的 N × d
token 3  ┘
```

这是**跨行**的操作：行与行之间交换信息。这是模型"理解上下文"的唯一途径，也是全课最核心的部分，C0-4 专门讲它。

### 子层 B：前馈网络（FFN / MLP）—— 纵向加工

**干什么**：对每一行**独立地**做一次非线性变换。行与行之间**不交互**。

```
token 1 的向量 → [升维 → 激活 → 降维] → 新的向量
token 2 的向量 → [升维 → 激活 → 降维] → 新的向量   （互不影响）
```

> 程序员类比：注意力是 `JOIN`（跨行），FFN 是 `MAP`（逐行）。

如果只有注意力没有 FFN，模型就只是"信息搬运工"——把别人的向量加权平均过来而已，没有产生新东西。FFN 提供的是**加工能力**：把混合后的信息做一次非线性变换，提炼出特征。

有个有意思的观察：现代模型里**FFN 占了大部分参数**（通常 2/3 以上）。有种观点认为 FFN 才是"知识库"——事实性知识主要存在这里，注意力负责"路由"。这个说法不严谨，但作为直觉够用。

## 3. 两个"配角"，各一句话

每层里还有两个辅助结构，你只需要知道它们为什么存在：

- **残差连接（Residual / Skip connection）**：`输出 = 输入 + 子层的计算结果`。保证信息不会在几十层的加工中丢失，也让梯度能传回去。类比：git 的增量提交，而不是每次全量覆盖。
- **Layer Normalization**：把每行的数值标准化到稳定范围。纯工程手段，防止数值爆炸/消失。

这两个不影响你的心智模型，知道它们在就行。

## 4. 为什么要堆很多层

越靠后的层，表示越抽象、越"高层"。一个常见（略粗糙但有用）的说法：

| 层位置 | 大致在学什么 |
|---|---|
| 浅层 | 词性、句法、局部搭配 |
| 中层 | 指代消解、实体关系 |
| 深层 | 语义意图、任务相关的抽象 |

层数越多，模型能表达的变换越复杂，能力越强——代价是算力和延迟线性增长。

## 5. 为什么是 Transformer，而不是 RNN

在 Transformer 之前，处理序列靠**RNN / LSTM**：一个 token 一个 token 顺着读，把"历史"压缩进一个隐藏状态往后传。

```
RNN:   token1 → state → token2 → state → token3 → ...   （严格串行）
```

**致命问题：无法并行。**算 token 3 必须等 token 2 算完。这在训练时是灾难——几万亿 token 的语料，串行下来根本训不完。

注意力机制的关键突破是：**一次就能算完所有位置之间的交互**，因为两两打分互不依赖，是一个大矩阵乘法。

```
Transformer:  [token1, token2, token3] → 一次矩阵乘法，全算完   （可并行）
```

这带来两个后果：

|  | RNN | Transformer |
|---|---|---|
| 训练 | 串行，慢到无法大规模 | 可并行，能堆到千亿参数 |
| 推理（生成） | 每步只看上一步状态，O(1) | 每步要回顾全部历史，O(N) |

**注意第二行的代价**：Transformer 用"训练能并行"换来了"推理时每步都要回头看全部历史"。这个代价正是 C2（KV Cache）要解决的问题——**它是 Transformer 架构自带的债**。

理解这一点，你就明白为什么 KV Cache 不是一个"优化技巧"，而是 Transformer 能实用的**前提条件**。

## 6. 一个现在就该注意的细节

注意第 1 节的图：我们要预测下一个 token 时，只取**最后一层、最后一个位置**的那一行。

为什么？因为生成时只有最后一个位置需要输出（前面的位置我们已经有答案了）。这一点在 C0-5 讲 prefill 时会很关键——它解释了为什么"输入处理"和"输出生成"是两种完全不同的计算模式。

## 7. 这一篇要带走的结论

1. 模型 = 对 N × d 的矩阵反复加工 L 次；形状不变，数字的含义在变。
2. 每层两个子层：**注意力做跨行混合（JOIN），FFN 做逐行加工（MAP）**。
3. 残差和 LayerNorm 是工程配件，知道存在即可。
4. Transformer 取代 RNN 是因为**训练可并行**，代价是**推理时每步要回顾全部历史**——这个代价就是 KV Cache 存在的理由。
5. 预测下一个 token 只用"最后一层最后一个位置"那一行。
