# C2-1 · 为什么需要 KV Cache
> 读之前
> ：这一篇直接用到了 token、向量、注意力、prefill / decode 这些概念。如果它们对你还是黑箱，先读 [C0 · 大模型工作原理速成](../00-c0-llm-fundamentals/README.md)（约 50-60 分钟，尤其 [C0-5](../00-c0-llm-fundamentals/05-full-inference-pipeline.md)），再回来读这里。

## 30 秒回顾（已读过 C0 可跳）

- 文本先被切成 token，换成整数 id，再查表变成向量 → 得到 N × d 的矩阵。
- 每一层里，每个 token 都从自己的向量投影出 Q（要找什么）、K（能被怎样匹配）、V（携带什么信息）。
- 用 Q 去和前面所有 K 打分，softmax 后加权求和所有 V，就是该 token 更新后的表示。
- 输入部分一次性并行算完（prefill），输出部分一个一个来（decode）。

## 1. 从自回归说起

语言模型生成文本的方式叫**自回归（autoregressive）**：一次只生成一个 token，把新 token 拼回序列，再预测下一个。

```
"今天" → 预测出 "天" → "今天天" → 预测出 "气" → "今天天气" → ...
```

要生成第 N 个 token，模型需要「看到」前面 N-1 个 token。这里的「看到」，在 Transformer 里就是**注意力（attention）**：每个 token 都要和它前面的所有 token 计算相关性。

## 2. 朴素实现有多浪费

最直白的实现是：每生成一个新 token，就把**整段序列**从头到尾重新过一遍网络。

问题来了。假设你要生成一段 2000 token 的回复：

- 生成第 1 个 token：模型处理 1000 个输入 token。
- 生成第 2 个 token：模型处理 1001 个 token。
- 生成第 3 个 token：模型处理 1002 个 token。
- ……
- 生成第 2000 个 token：模型处理 3000 个 token。

**前 1000 个 token 被反复处理了 2000 次**，每次算出来的东西几乎一模一样。这就像你要抄一篇文章，每抄一个字都把已经抄过的所有字重新抄一遍——前 999 个字被你反复重写了 2000 遍。

这就是 KV Cache 要消灭的浪费。

## 3. 用注意力精确定位「浪费在哪」

注意力做的事，可以浓缩成三步（每个 token 都做）：

1. 当前 token 投影出一个**查询向量 Q**（我要找什么）。
2. 每个 token 都投影出**键向量 K**（我是什么）和**值向量 V**（我携带什么信息）。
3. 用 Q 和所有前面的 K 做点积打分，softmax 归一化后，加权求和所有前面的 V。

关键观察：当你从「生成第 N 个 token」走到「生成第 N+1 个 token」时：

- **前面所有 token 的 K 和 V 一点都没变**（它们只取决于自己，不取决于未来）。
- 变的只有「新增 token 的 Q」，以及「新增 token 自己的 K、V」。

所以前面 token 的 K、V 是**可以存起来重复用**的，而不是每个生成步骤都重算。这就是 KV Cache 的由来——**把已经算过的 K、V 存进显存，后续只算新 token 的那一份**。

## 4. 一句话直觉

> KV Cache 就是「把已经算出来的中间结果（K 和 V）缓存住，避免每生成一个字都把整段历史重算一遍」。

它和我们熟悉的**动态规划 / 备忘录（memoization）**是同一个思想：用空间（显存）换时间（算力）。

## 5. 收益有多大

- **算力**：生成第 N 个 token 时，原本要处理全部 N 个 token，现在只需要处理「新增的 1 个 token」+「读取前面 N-1 个 token 的 K/V」。矩阵乘法的计算量从「随 N 平方增长」降到「随 N 线性增长」。
- **速度**：这是决定推理吞吐的根本。没有 KV Cache，长文本生成会慢到不可用。
- **这是所有大模型推理框架（vLLM、TensorRT-LLM、SGLang 等）存在的第一理由。**

## 6. 代价预告：显存

天下没有免费的午餐。KV Cache 的代价是**显存**：

- 序列越长，缓存越大。
- 同时服务的并发请求越多，缓存总量越大。

粗略量级：一个 7B 模型，每生成 1 个 token，KV Cache 大约占**0.5 MB 显存**；1000 个 token 就是 0.5 GB（精确算法和例子见 C2-3）。

这也解释了两个现象：

1. 为什么「上下文窗口」不是无限大——显存和带宽撑不住。
2. 为什么厂商的「缓存折扣」能省那么多钱——他们省的就是这一大块重复的显存读写和计算。
