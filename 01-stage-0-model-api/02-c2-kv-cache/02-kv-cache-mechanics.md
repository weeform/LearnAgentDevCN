# C2-2 · KV Cache 原理：Q / K / V
## C2-2 · KV Cache 原理：Q / K / V 与「为什么 K、V 不会变」

> 这一篇是整个 C2 的地基。看懂它，后面所有优化、所有厂商缓存行为都是顺理成章的推论。

> 前置要求
> ：这一篇开篇就用「隐藏表示」「投影」「权重矩阵」，并且假定你已经知道 Q / K / V 分别是什么。如果还不熟，请先读 [C0-3 Transformer 骨架](../00-c0-llm-fundamentals/03-transformer-block-anatomy.md) 和 [C0-4 注意力与 Q / K / V](../00-c0-llm-fundamentals/04-attention-qkv.md)。C0-4 是本篇的直接前置，读它之前看这里会十分吃力。

## 30 秒回顾：Q / K / V 分别是什么

- **Q（Query）**：这个 token 想找什么。只在“当前这一步查询”时用，用完即弃。
- **K（Key）**：这个 token 能被怎样检索。只由它自己决定，不随生成过程变化。
- **V（Value）**：匹配上了交出去的信息内容。同样只由它自己决定。

三个向量都是由该 token 自己的输入向量乘上不同的可学习矩阵得到的——记住这一点，本篇的核心结论就是它的直接推论。

## 1. 每个 token 先投影出三组向量

模型处理到某个 token 时，会先算出它的隐藏表示，再通过三个可学习的权重矩阵，投影成三组向量：

- **Q（Query，查询）**：这个 token「想去关注什么 / 找什么」。
- **K（Key，键）**：这个 token「是什么，能被别人怎样定位」。
- **V（Value，值）**：这个 token「实际携带的信息内容」。

用「查字典」打比方：你要找一条信息（Q），书里每个词条都有一个标题（K）和正文（V）。你用 Q 去和所有 K 匹配，找到相关词条后，读的是它们的 V。

注意：**每个 token 的 Q、K、V 都只由这个 token 自己的输入决定**，跟序列里其它 token 无关。这是后面一切结论的前提。

## 2. 注意力是怎么算的

对第 i 个 token，要算它对前面所有 token（含自己）的注意力：

```
scores_ij = (Q_i · K_j) / sqrt(d)     # d 是每个头的维度，sqrt(d) 是缩放防止数值过大
weights_i  = softmax(scores_i)         # 归一化成概率
output_i   = Σ_j weights_ij · V_j      # 用权重加权求和所有的 V
```

再加上**因果掩码（causal mask）**：第 i 个 token 只允许看到 j ≤ i 的 token，j > i 的位置分数被置为 -inf（softmax 后为 0）。这就是「只看前面、不看未来」。

## 3. 核心结论：为什么偏偏 K 和 V 能缓存

关键就在「因果」二字。

因为第 i 个 token 只能看到 j ≤ i，所以：

- `K_j` 和 `V_j` 只参与「所有 i ≥ j 的 token」的注意力计算。
- 当你在生成第 i 个 token 时，对于所有 j \< i，`K_j`、`V_j`**在之前的步骤里就已经被完整算过了，而且之后不会再变**——因为它们只依赖 token j 自己，而 token j 早就确定了。

那 Q 呢？

- `Q_i` 只在「生成第 i 个 token」这一步被使用，用完就再也不会用到（因为未来的 token 用的是它们自己的 Q）。
- 所以 Q 没有缓存价值——**每个 Q 都是「一次性」的**。

于是结论很干净：

> **K 和 V 是「跨步骤复用」的，所以缓存；Q 是「一次性的」，所以不缓存。**

这也是为什么它叫「KV Cache」而不是「QKV Cache」。

## 4. 一个逐步走一遍

假设序列是 [你, 好]，正在生成第 3 个 token。

**第一步（处理「你」）**：算出 `Q_你, K_你, V_你`。此刻「你」只看得到自己。  
**第二步（处理「好」）**：算出 `Q_好, K_好, V_好`。用 `Q_好` 去和 `K_你, K_好` 打分，加权 `V_你, V_好`。  
**第三步（生成新 token）**：只算出 `Q_新, K_新, V_新`。用 `Q_新` 和**缓存的**`K_你, K_好` + 新的 `K_新` 打分，加权缓存的 `V_你, V_好` + `V_新`。

注意第三步：`K_你, V_你, K_好, V_好` 全部直接复用，一行都没重算。然后把 `K_新, V_新` 追加进缓存，供下一步使用。

每一步真正的新计算量 = 1 个 token 的 Q/K/V + 一次注意力（对全部 K 打分）。历史 token 的 K/V 是「读」而不是「算」。

## 5. 由此直接推出的两条铁律

**铁律一：前缀必须逐字节精确匹配，才能复用。**

缓存的键是「前面那串 token 的 K/V」。只要前缀里任何一个 token 变了（哪怕一个空格、一个大小写），从那个位置开始的所有 K/V 就全都变了，缓存从断裂点起全部作废。这就是为什么各家都强调「缓存命中只对**完全相同的前缀**生效」。

**铁律二：可变内容放后面，稳定内容放前面。**

因为缓存只能复用「前缀」。稳定不变的（system prompt、工具定义、共享文档）放最前面形成长前缀；每次都变的（用户问题、当轮结果）放最后，这样前面一大段每次都能命中。
