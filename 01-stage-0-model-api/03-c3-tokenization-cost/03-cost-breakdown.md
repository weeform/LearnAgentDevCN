# C3-3 · 成本结构：一次调用的钱花在哪
> 阅读约 13 分钟。含 **2026-11 的价格快照**，但**价格会变，请以官方定价页为准**——这篇真正要你带走的是**算法**，不是数字。

## 1. 四个计价桶

一次调用的费用，由四类 token 各自乘以不同单价构成：

| 桶 | 说明 | 相对价格 |
|---|---|---|
| **输入** | prompt、历史、工具定义 | 基准 1x |
| **缓存命中输入** | 命中前缀缓存的部分 | 0.02～0.1x（省 90%～98%） |
| **缓存写入** | 首次写入缓存的部分 | 1.25x（5 分钟）／2x（1 小时） |
| **输出** | 模型生成的内容，**含推理 token** | 通常 4～10x |

两个容易忽略的点：

- **推理/思考 token 按输出计费**。开了 reasoning 的模型，那些"看不见的思考"是要付钱的，而且占上下文窗口（C1 已提）。
- **缓存写入比普通输入贵**。所以缓存不是免费的，前缀不稳定时反复写入反而更贵（C2-5 详述）。

## 2. 公式

```
cost = (in_full  / 1e6) × P_in
     + (in_cached / 1e6) × P_cached
     + (in_write  / 1e6) × P_write
     + (out       / 1e6) × P_out
```

就这么简单。难的是 `in_full` 在 Agent 里会滚雪球。

> **价格快照说明**：下表是 **2026-11-01** 从各厂商官方定价页核实的数字，只用来把算法算给你看。它一定会过时——下单前请回去看一眼官网。换个价格套同一个式子，结论依然成立。

|---|---|---|---|---|

| GPT-6.1 Sol | $2.00 | $0.10 | $10.00 | 1.05M |
| GPT-6 Luna（最省） | $0.10 | $0.01 | $0.50 | 1.05M |
| Claude Fable 5.1（旗舰） | $10.00 | $0.25 | $50.00 | 1M |
| Claude Opus 5.5 | $4.00 | $0.20 | $20.00 | 1M |
| Claude Haiku 5.5（≤100K 提示） | $0.10 | $0.01 | $0.50 | 1M\* |
| Claude Haiku 4.5 | $1.00 | $0.10 | $5.00 | 200K |
| deepseek-flash（闲时） | $0.15 | $0.003 | $0.60 | 1M |

\* Haiku 5.5 是唯一按提示长度分级计价的：提示超过 100K token 时，三档单价分别升到 `$0.50 / $0.05 / $2.50`。这类"看起来最便宜、用长了并不便宜"的定价结构，选型时要特别留意。

四个观察：

1. **输出几乎正好是输入的 5 倍**（DeepSeek 是 4 倍）。这么多家、这么多档位都落在同一个比例上，说明它不是营销定价，而是**在反映真实的计算量差异**——所以"让模型少说两句"永远是有效手段。
2. **同代家族内的价差到了 100 倍**（Astra `$10` vs Luna `$0.10`；Fable 5.1 `$10` vs Haiku 5.5 `$0.10`）。模型分级是最猛的降本杠杆，没有之一。
3. **缓存读的折扣越给越狠**：从 0.1×（省 90%）一路到 deepseek-flash 的 0.02×（省 98%）。但**缓存写入仍要 1.25×（5 分钟）/ 2×（1 小时）**——读越来越便宜、写一直不便宜，所以"前缀稳定"比任何时候都值钱（下一节有账）。
4. **1M 上下文已成标配**（GPT-6 全系 1.05M、Claude 5.5 系 1M、DeepSeek 全系 1M）。但"能塞"不等于"该塞"——1M 的 prefill 要几十秒，价格还有跳档（见 C22-4）。

> 还有一条不算价格、但同样影响账单的：**不同厂商、不同代际的分词器不一样**，同一段中英混排的文本，token 数能差两三成。所以"换模型"必须**重新数 token**，不能拿旧账单按 token 数直接换算。

## 4. 算例 1：单次问答

条件：system + tools = 2000 token，用户问题 500 token，回答 400 token。

```
GPT-6.1 Sol:     2500/1e6×2  + 400/1e6×10 = $0.0050 + $0.0040 = $0.0090
Claude Opus 5.5: 2500/1e6×4  + 400/1e6×20 = $0.0100 + $0.0080 = $0.0180
GPT-6 Astra:     2500/1e6×10 + 400/1e6×50 = $0.0250 + $0.0200 = $0.0450
```

单次：不到 1 美分到 4.5 美分。看起来都不贵——**这就是陷阱**，因为 Agent 不调一次。

## 5. 算例 2：Agent 循环（重点）

设：稳定前缀（system + tools）`B = 2500`，每步新增（工具结果 + 回复）`S = 700`，跑 `n = 10` 步，每步输出 200。

第 k 步的输入是 `B + k·S`（历史全量重发，因为 API 无状态）。所以：

```
总输入 ≈ n·B + S·n(n−1)/2
       = 10×2500 + 700×45 = 25,000 + 31,500 = 56,500
总输出 = 10×200 = 2,000

GPT-6.1 Sol:  56,500/1e6×2  + 2,000/1e6×10 = $0.1130 + $0.0200 = $0.1330
GPT-6 Astra:  56,500/1e6×10 + 2,000/1e6×50 = $0.5650 + $0.1000 = $0.6650
GPT-6 Luna:   56,500/1e6×0.1+ 2,000/1e6×0.5= $0.0057 + $0.0010 = $0.0067
```

**一次任务 13 美分（中档 Sol）。**一天 1000 次任务 =**$133/天 ≈ $4,000/月**。

换个模型看看这同一份活的价差：旗舰 Astra **$665/天 ≈ $20,000/月**，最省的 Luna **$7/天 ≈ $200/月**——同一套代码、同一个任务、**二十倍的钱**。这就是为什么 C22 要专门讲分级路由：选型一个决定，比你在 prompt 上抠半天都值钱。

再看步数翻倍的威力：

| 步数 n | 总输入 token | 相对成本 |
|---|---|---|
| 5 | 19,500 | 1.0x |
| 10 | 56,500 | 2.9x |
| 20 | 183,000 | 9.4x |
| 40 | 646,000 | 33.1x |

**步数翻倍，成本涨约 3～4 倍**——这就是 `S·n²/2` 那一项在发力。Agent 的成本曲线是**平方级**的，不是线性的。

> 这就是为什么"最大步数"这个参数（阶段 2 会讲）不只是防死循环，也是**成本控制阀门**。

## 6. 算例 3：开缓存能省多少

关键结论先说：**缓存省多少，取决于稳定前缀在总输入里占多大比例**，不是无脑 90%。

**场景 A：稳定前缀小**（B=2400，S=700，n=10，按 GPT-6.1 Sol 的价）

```
命中部分：24,000 × $0.10 /1M = $0.0024
其余输入：31,500 × $2.00 /1M = $0.0630
输出：     2,000 × $10   /1M = $0.0200
合计 $0.0854  （无缓存 $0.1310 → 省 35%）
```

**场景 B：稳定前缀大**（长文档 RAG，B=8000，S=500，n=10）

```
无缓存：102,500 × $2.00 /1M = $0.2050，加输出 $0.0200 = $0.2250
有缓存： 80,000 × $0.10 /1M + 22,500 × $2.00 /1M + 输出
       = $0.0080 + $0.0450 + $0.0200 = $0.0730  → 省 68%
```

**所以**：想靠缓存省钱，先问"我的稳定前缀有多少 token"。前缀越长、占比越高，省得越多。少于 1024 token 的前缀**根本不会触发缓存**（OpenAI 门槛），这也是 C2-5 那六条设计模式存在的理由。

**反面也要算一遍**：如果前缀不稳定、每一步都重写缓存，按 1.25× 的写入价算，同样场景 A 会花到 **$0.1430**——比稳定前缀的 $0.0854 **贵了 67%**。缓存不是"开了就省"，写坏了比不开还贵。

> 把上面三组数字里的单价换成你查到的当前价，套同一个式子，结论照样成立——**公式稳定，价格不稳**。

## 7. 输出侧省钱：被低估的一块

输出单价是输入的 4～10 倍，所以：

- **设 `max_completion_tokens`**：既是护栏也是预算上限；
- **用 `verbosity` 参数**（GPT-6 系列、GPT-5 系列支持）：直接从模型侧压低啰嗦程度；
- **别让模型重复你的输入**：要求"只输出结论，不要复述问题"；
- **结构化输出反而省钱**：只输出字段，不输出寒暄——`{"city":"北京"}` 比 "好的，根据您的问题，这座城市是北京。" 便宜一个数量级。

## 8. 小结

- 成本 = 四类 token × 四种单价，**输出最贵**。
- Agent 的总输入 ≈ `n·B + S·n²/2` ——**平方增长**，步数是最敏感的变量。
- 缓存收益由**稳定前缀占比**决定，不是固定的 90%。
- 换模型要重量 token（分词器差异），换模型要重算账（同代价差可达 100 倍）。

## 思考题

> 先自己答，再展开参考思路。这三问不考记忆，考的是你能不能把它用在自己的项目上。

1. 输出为什么最贵？贵在单价还是贵在「它还要被反复读」？
2. Agent 总输入 ≈ n·B + S·n²/2，为什么步数 n 是最敏感的变量？
3. 缓存收益由「稳定前缀占比」决定，而不是固定的 90%。你怎么把这个占比提上去？

<details>
<summary>参考思路</summary>

1. 两头都有：输出单价通常是输入的 3–5 倍；而且输出还会进入下一轮上下文，被后续每一步重复读取。所以「话多」在 Agent 里是双重收费。
2. 因为它同时出现在两项里：线性项 n·B，和平方项 S·n²/2。n 从 5 涨到 10，总输入不是翻倍，而是接近三倍。控制步数比压缩单步长度更有效。
3. 把不变的东西（system prompt、工具定义、固定示例、长期记忆摘要）全部前置且措辞固定，易变的（用户本轮输入、临时检索结果）全部后置。前缀越稳定、越长，命中率越高。
