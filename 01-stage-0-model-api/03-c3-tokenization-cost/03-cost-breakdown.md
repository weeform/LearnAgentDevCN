# C3-3 · 成本结构：一次调用的钱花在哪
> 阅读约 13 分钟。含截至 2026-09 的真实价格，但**价格会变，请以官方定价页为准**——这篇真正要你带走的是**算法**，不是数字。

## 1. 四个计价桶

一次调用的费用，由四类 token 各自乘以不同单价构成：

| 桶 | 说明 | 相对价格 |
|---|---|---|
| **输入** | prompt、历史、工具定义 | 基准 1x |
| **缓存命中输入** | 命中前缀缓存的部分 | 通常 0.1x（省 90%） |
| **缓存写入** | 首次写入缓存的部分 | 1.25x（5 分钟）／2x（1 小时） |
| **输出** | 模型生成的内容，**含推理 token** | 通常 4～10x |

两个容易忽略的点：

- **推理/思考 token 按输出计费**。开了 reasoning 的模型，那些"看不见的思考"是要付钱的，而且占上下文窗口（C1 已提）。
- **缓存写入比普通输入贵**。所以缓存不是免费的，前缀不稳定时反复写入反而更贵（C2-5 详述）。

## 2. 公式

```
cost = (in_full  / 1e6) × P_in
     + (in_cached / 1e6) × P_cached
     + (in_write  / 1e6) × P_write
     + (out       / 1e6) × P_out
```

就这么简单。难的是 `in_full` 在 Agent 里会滚雪球。

三个观察：

3. **Claude 4.7+ 换了分词器，同样文本约多 30% token**——标价没变，实际单价涨了三成。

## 4. 算例 1：单次问答

条件：system + tools = 2000 token，用户问题 500 token，回答 400 token。

```
GPT-5:        2500/1e6×1.25 + 400/1e6×10  = $0.0031 + $0.0040 = $0.0071
Opus 4.8:     2500/1e6×5    + 400/1e6×25  = $0.0125 + $0.0100 = $0.0225
```

单次：不到 1 美分 vs 2 美分。看起来都不贵——**这就是陷阱**，因为 Agent 不调一次。

## 5. 算例 2：Agent 循环（重点）

设：稳定前缀（system + tools）`B = 2500`，每步新增（工具结果 + 回复）`S = 700`，跑 `n = 10` 步，每步输出 200。

第 k 步的输入是 `B + k·S`（历史全量重发，因为 API 无状态）。所以：

```
总输入 ≈ n·B + S·n(n−1)/2
       = 10×2500 + 700×45 = 25,000 + 31,500 = 56,500
总输出 = 10×200 = 2,000

GPT-5:  56,500/1e6×1.25 + 2,000/1e6×10 = $0.0706 + $0.0200 = $0.0906
```

**一次任务 9 美分。**一天 1000 次任务 =**$90/天 ≈ $2,700/月**。

再看步数翻倍的威力：

| 步数 n | 总输入 token | 相对成本 |
|---|---|---|
| 5 | 19,500 | 1.0x |
| 10 | 56,500 | 2.9x |
| 20 | 183,000 | 9.4x |
| 40 | 657,000 | 33.7x |

**步数翻倍，成本涨约 3～4 倍**——这就是 `S·n²/2` 那一项在发力。Agent 的成本曲线是**平方级**的，不是线性的。

> 这就是为什么"最大步数"这个参数（阶段 2 会讲）不只是防死循环，也是**成本控制阀门**。

## 6. 算例 3：开缓存能省多少

关键结论先说：**缓存省多少，取决于稳定前缀在总输入里占多大比例**，不是无脑 90%。

**场景 A：稳定前缀小**（B=2400，S=700，n=10）

```
命中部分：24,000 × $0.125/1M = $0.0030
其余输入：32,500 × $1.25 /1M = $0.0406
输出：     2,000 × $10   /1M = $0.0200
合计 $0.0636  （无缓存 $0.0906 → 省 30%）
```

**场景 B：稳定前缀大**（长文档 RAG，B=8000，S=500，n=10）

```
无缓存：102,500 × $1.25 /1M = $0.1281
有缓存： 80,000 × $0.125/1M + 22,500 × $1.25/1M + 输出
       = $0.0100 + $0.0281 + $0.0200 = $0.0581  → 省 55%
```

**所以**：想靠缓存省钱，先问"我的稳定前缀有多少 token"。少于 1024 token 的前缀**根本不会触发缓存**（OpenAI 门槛），这也是 C2-5 那六条设计模式存在的理由。

## 7. 输出侧省钱：被低估的一块

输出单价是输入的 4～10 倍，所以：

- **设 `max_completion_tokens`**：既是护栏也是预算上限；
- **用 `verbosity` 参数**（GPT-5 系列支持）：直接从模型侧压低啰嗦程度；
- **别让模型重复你的输入**：要求"只输出结论，不要复述问题"；
- **结构化输出反而省钱**：只输出字段，不输出寒暄——`{"city":"北京"}` 比 "好的，根据您的问题，这座城市是北京。" 便宜一个数量级。

## 8. 小结

- 成本 = 四类 token × 四种单价，**输出最贵**。
- Agent 的总输入 ≈ `n·B + S·n²/2` ——**平方增长**，步数是最敏感的变量。
- 缓存收益由**稳定前缀占比**决定，不是固定的 90%。
- 换模型要重量 token（分词器差异），换模型要重算账（价差可达 25 倍）。
