# C3-4 · 上下文预算表、降本优先级与自测
> 阅读约 12 分钟。这一篇是 C3 的"落地页"：把前面所有结论压成一张表和一份清单。

## 1. 上下文预算表（可直接抄）

设计 Agent 时，先给上下文**分区定额**，而不是"用到哪算哪"。下面是一个 128K 窗口的参考分配：

| 分区 | 建议占比 | 128K 下的额度 | 说明 |
|---|---|---|---|
| system + 工具定义 | 5～10% | 6K～13K | 必须**完全稳定**，放最前，吃缓存 |
| 长期背景 / 检索文档 | 20～40% | 25K～50K | 稳定，放 system 之后 |
| 对话历史（压缩后） | 20～30% | 25K～38K | 唯一会增长的部分 |
| 当前工具结果 | 10～20% | 13K～25K | 最容易爆，需设上限 |
| 输出预留 | 10～15% | 13K～19K | 必须留，否则 `finish_reason=length` |
| **安全余量** | **10%** | **13K** | 应对 token 估算误差 |

三条使用规则：

1. **任何一个分区超配额，就触发对应策略**（摘要 / 截断 / 丢弃 / 报错），不要等整个窗口满了才处理；
2. **输出预留是硬性的**——输入 + `max_completion_tokens` 必须小于窗口，超了直接 400；
3. **安全余量不能省**，因为你的 token 估算有 10～30% 误差（C3-2）。

## 2. 降本手法优先级（按性价比排序）

从上往下做，投入产出比依次递减：

| 优先级 | 手段 | 典型收益 | 风险 |
|---|---|---|---|
| 1 | **模型分级路由**（简单任务用小模型） | 5～25 倍 | 需评测兜底 |
| 2 | **缩短上下文**（裁剪/摘要/只回必要字段） | 30～70% | 可能丢信息 |
| 3 | **稳定前缀 + 缓存** | 输入侧 30～70% | 要求前缀稳定 |
| 4 | **限制输出长度**（verbosity / max_tokens / 结构化输出） | 20～50% | 低 |
| 5 | **工具返回值瘦身**（minify、分页、字段白名单） | 10～40% | 低 |
| 6 | **Batch API 处理离线任务** | 约 50% | 只适合非实时 |
| 7 | 自部署 / 蒸馏 / 量化 | 视规模 | 高，阶段 5 之后再考虑 |

为什么**模型分级排第一**：同家族内价差可达 25 倍（C3-3 的表），这是唯一能带来数量级变化的手段。前提是——你得有一个评测集来判断"小模型够不够用"（阶段 5 的活，但你应该现在就开始攒测试用例）。

为什么**缓存不是第一**：它只作用于输入，且受稳定前缀占比约束。它很重要（C2 整门课都在讲），但别把它当成万能药。

## 3. 反模式清单（见到就改）

| 反模式 | 为什么错 | 改法 |
|---|---|---|
| 历史消息无上限追加 | 平方级涨成本 | 超过 N 轮就摘要 |
| 工具返回全量 JSON pretty-print | 空格也计费，可差一倍 | minify + 字段白名单 |
| 为了凑缓存门槛往前缀里注水 | 写入更贵，且可能挤掉有用内容 | 顺其自然，不够就不缓存 |
| 每步都把完整检索结果塞进去 | 重复计费 | 检索结果放前、按需加载 |
| 从不设 `max_completion_tokens` | 输出是输入的 4～10 倍价 | 必设 |
| 用旗舰模型跑分类/抽取 | 杀鸡用牛刀 | 路由到 nano/mini 级 |
| 只看账单不看 `usage` | 出事时无法定位 | 埋点（下一节） |

## 4. 成本监控：必须记录的字段

最少记录这些，才能回答"钱花在哪了"：

- `request_id` / `session_id` / `step_index`
- `model`
- `prompt_tokens` / `cached_tokens` / `completion_tokens`
- `tools_count` / `messages_count`
- `finish_reason`
- `latency_ms`

有了 `step_index`，你能画出**每一步的输入增长曲线**——这张图会非常直观地告诉你，是工具返回值太胖，还是历史没裁剪。

## 5. 自测题（10 道）

> 先自己答，再看答案要点。答对 7 道以上，C3 可以过关。

1. 同一份 system prompt 从 Claude 4.6 迁移到 4.8，标价没变，为什么账单会涨？
2. 一段 pretty-print 的 JSON 和 minify 后，token 数大概差多少？
3. 为什么按字符截断（`text[-8000:]`）是危险的？正确做法是什么？
4. 10 步 Agent 循环，稳定前缀 2500、每步新增 700，总输入大约多少 token？
5. 上题中，步数从 10 增加到 20，成本大约变成几倍？为什么？
6. 缓存命中能省 90% 输入成本，为什么实际任务往往只省 30%？
7. 输出 token 和输入 token 相比，通常贵多少倍？这对 prompt 设计有什么启示？
8. 为什么"模型分级"是收益最大的降本手段？它的前提条件是什么？
9. 工具定义为什么是"隐形固定成本"？10 个工具跑 10 步意味着什么？
10. 设计上下文预算时，为什么要留 10% 安全余量？

### 答案要点

1. Claude 4.7+ 换用新分词器，同样文本约多 30% token。
2. 大约差一倍（缩进、换行、空格都算 token）。
3. 会切在 token 中间或字符中间产生乱码/非法字符串；应在 token 层面 encode → 切 → decode。
4. `10×2500 + 700×(0+…+9) = 25,000 + 31,500 = 56,500`。
5. 约 3～4 倍。总输入含 `S·n²/2` 项，是平方增长。
6. 因为缓存只作用于**稳定前缀**；前缀占比小（如 2400/5650）时，整体折扣被摊薄。
7. 约 4～10 倍。启示：限制输出长度、用结构化输出、别让模型复述输入。
8. 同家族价差可达 25 倍，是数量级差异。前提：有评测集判断小模型是否够用。
9. 每次请求都要重发工具 schema，每个 50～300 token。10 工具 × 10 步 = 工具定义被计费 10 遍。
10. token 估算有 10～30% 误差，且输出预留之外的空间需要缓冲，否则容易触发超窗口报错。
