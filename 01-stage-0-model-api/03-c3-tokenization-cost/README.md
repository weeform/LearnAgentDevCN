# C3 · Token、分词与成本模型
> 阶段 0 · 模型调用与参数原理 的第三门课。  
> C1 讲了「有哪些旋钮」，C2 讲了「请求在服务端经历了什么」，这门课回答最后一个问题：**这些旋钮拧下去，到底花多少钱。**

## 为什么 Agent 开发者必须比普通人更懂 token

普通应用调一次大模型，成本是一次性的。Agent 不一样：

- **一次任务 = 几十次调用**；
- **每一步都把前面所有历史重新发一遍**；
- 上下文随步数**线性增长**，总成本**平方增长**。

这意味着 Agent 里一个"看着不起眼"的字符串，会被重复计费几十次。C1 里学的每个参数（max_tokens、tools、response_format），背后都挂着价格标签。这门课就是把价格标签全部翻过来给你看。

## 课程结构（约 45–60 分钟）

| 篇目 | 主题 | 你会得到什么 |
|---|---|---|
| C3-1 | Token 与分词：BPE 直觉与 6 个坑 | 能对任意文本预估 token 量级，知道哪些写法在烧钱 |
| C3-2 | 怎么数 token：工具、误差与估算公式 | 一套本地数 token 的方法，误差可控在 10% 内 |
| C3-3 | 成本结构：一次调用的钱花在哪 | 会算单次成本，会算 Agent 循环的 O(n²) 放大 |
| C3-4 | 上下文预算表与降本优先级 | 一份能直接抄的预算表 + 自测题 |

## 学完你应该能做到

1. 拿到一段 system prompt + 工具定义，估出它占多少 token，误差 \< 15%；
2. 估算一个 10 步 Agent 任务的月度成本，并说出降本 50% 的具体改法；
3. 解释为什么「把工具返回值全量塞回上下文」是 Agent 最典型的烧钱点。

## 贯穿这门课的一句话

> **成本不是优化阶段才考虑的事，它是设计阶段就要算清楚的量。**

C3-1 从最底层开始：token 究竟是怎么切出来的。
