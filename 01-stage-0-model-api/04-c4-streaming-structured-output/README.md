# C4 · 流式输出与结构化输出
> 阶段 0 · 模型调用与参数原理 的第四门课。  
> C1 讲了参数，C2 讲了原理，C3 讲了成本。这门课解决两个"一写代码就会撞上"的问题：**怎么边生成边拿结果**，以及**怎么让模型稳定吐出机器能解析的内容**。

## 为什么这两件事必须一起讲

Agent 的核心循环是「模型输出 → 你的代码解析 → 决定下一步」。这个链条上有两个脆弱点：

1. **流式**：你拿到的不是一个完整对象，而是几十上百个碎片，拼错了就会出现"JSON 少了个括号"这种诡异 bug；
2. **结构化**：模型输出的文本天生不可信，它可能加废话、加 markdown 围栏、或者被 `max_tokens` 拦腰截断。

这两块处理不好，Agent 会表现为"偶尔抽风"——而且极难复现。

## 课程结构（约 45–60 分钟）

| 篇目 | 主题 | 你会得到什么 |
|---|---|---|
| C4-1 | 流式输出：SSE 协议与增量解析 | 能手写流式读取，知道心跳、断流怎么处理 |
| C4-2 | 工具调用的流式拼接 | 一个不会出错的累加器写法，避开 5 个经典 bug |
| C4-3 | 结构化输出：JSON Schema 与 strict 模式 | 知道三种路线的取舍，会写合规 schema |
| C4-4 | 解析容错与失败恢复 | 一套三级修复流水线 + 自测 |

## 学完你应该能做到

1. 不用 SDK 也能从 HTTP 流里正确读出文本与工具调用；
2. 写出一个支持**并行工具调用**的流式累加器；
3. 为一个业务对象写出能通过 strict 模式的 JSON Schema；
4. 设计一条"模型输出 → 可信对象"的解析流水线，失败率可控。

## 一句话原则

> **模型输出是不可信输入。**流式让它变碎，结构化让它变可信——两件事都要在你的代码里显式处理，不能指望模型自觉。
