# C5-1 · 错误全景：状态码与可重试性
> 阅读约 11 分钟。目标：拿到任意错误，30 秒内判断出该不该重试。

## 1. 先分三类，别只看状态码

比背状态码更重要的一件事：把错误分成**三类**，每类的处理动作完全不同。

| 类别 | 含义 | 动作 |
|---|---|---|
| **A. 瞬时错误** | 服务端临时故障、限流、网络抖动 | **重试**（退避后） |
| **B. 永久错误** | 参数写错、鉴权失败、模型不存在 | **不重试**，改代码/配置并告警 |
| **C. 输入相关** | 上下文超长、内容被过滤、schema 不合法 | **改输入**后再试（有次数上限） |

**对 B 类错误重试是最蠢的行为**：它会立刻再失败一次，还会浪费配额、污染监控。

## 2. 状态码决策表

| 码 | 典型含义 | 类别 | 动作 |
|---|---|---|---|
| 400 | 请求不合法（参数错、schema 错） | B | 不重试，修参数，记录请求体 |
| 401 | 密钥无效 | B | 不重试，告警（可能是密钥被吊销） |
| 403 | 无权限 / 区域限制 | B | 不重试，检查权限与区域 |
| 404 | 模型或端点不存在 | B | 不重试，检查模型名 |
| 409 | 冲突（部分厂商） | A/B | 看错误码判断 |
| 422 | 参数校验失败 | B | 不重试 |
| **429** | **限流或配额耗尽** | **A（配额类除外）** | **退避重试，尊重 Retry-After** |
| 500 | 服务端内部错误 | A | 退避重试 |
| 502 / 503 | 网关/服务不可用 | A | 退避重试 |
| 504 | 网关超时 | A | 谨慎重试（可能是长请求） |
| **超时** | 客户端读超时 | **A（不确定）** | 见第 4 节 |
| 特殊：`context_length_exceeded` | 输入超窗口 | C | **压缩上下文后重试** |
| 特殊：`content_filter` | 内容被安全策略拦截 | C | 改输入或走人工 |

## 3. 错误体里有什么

典型结构（各厂商字段名略有差异）：

```json
{
  "error": {
    "message": "This model's maximum context length is 128000 tokens...",
    "type": "invalid_request_error",
    "code": "context_length_exceeded"
  }
}
```

三个必须抓的东西：

1. **`code`**——比 HTTP 状态码更精确，是判断类别的**第一依据**（同样是 400，可能是 schema 错，也可能是上下文超长，处理完全不同）；
2. **`message`**——给人看的，进日志；
3. **响应头里的 request id**（如 `x-request-id`）——**必存**。出问题时你要拿它找厂商支持，没有它基本无法排查。

## 4. 最麻烦的一种：超时

超时之所以讨厌，是因为你**不知道服务端到底执行了没有**：

- 请求没到服务端 → 重试安全；
- 请求到了、正在算 → 重试会**重复计费**；
- 请求算完了、响应回程丢了 → 重试同样重复计费。

处理原则：

1. **区分连接超时与读超时**：连接超时（几秒）说明大概率没到服务端，可立即重试；读超时说明请求已发出，要谨慎。
2. **设两个超时**：`connect_timeout`（5～10 秒）+ `read_timeout`（按场景，长任务可 60 秒以上）；流式场景用**首 token 超时**（TTFT）单独控制，避免"卡住 60 秒才报错"。
3. **用业务幂等键去重**：自己生成 `request_id` 并在服务端去重，避免重试造成重复副作用（如重复下单、重复发邮件）。

## 5. 上下文超长（C 类的典型）

`context_length_exceeded` 是 Agent 最常见的一类错误，因为它会随步数自然发生。处理链：

```
检测到超长
  → ① 压缩历史（摘要老的对话轮次）
  → ② 裁剪工具返回值（只留关键字段）
  → ③ 减少/移除检索文档
  → ④ 仍然超长 → 拆任务或报错
```

配套动作：**预防优于治疗**。按 C3-4 的预算表，在接近阈值时（比如 80%）就主动压缩，而不是等 API 报错。

## 6. 流式中途失败

表现：数据读到一半连接断了（C4-1）。

- 已收到的内容**无法续传**；
- 简单重试 = 重新生成 = 内容可能不同 + 重复花钱；
- 建议：**保留部分内容**，把重开作为用户可选项；对中间步骤则直接重试（反正不要部分结果）。

## 7. 小结

- 先分类（瞬时 / 永久 / 输入相关），再决定动作，**不要对 B 类重试**。
- 以**`error.code`**为准，不要只看 HTTP 状态码。
- **必存 request id**，否则无法排查。
- 超时的本质是"不知道有没有执行"，靠**两个超时 + 业务幂等键**处理。
- 上下文超长属于 C 类：压缩后重试，并用预算表提前预防。
