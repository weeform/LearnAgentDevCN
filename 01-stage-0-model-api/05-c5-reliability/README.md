# C5 · 稳定性：错误、重试、限流与降级
> 阶段 0 的最后一门课，也是阶段 0 的收尾。  
> 前面四门课都假设"调用成功"。现实是：调用会失败、会被限流、会超时。**Agent 的可靠性，90% 取决于这层做得怎么样。**

## 为什么这门课放在阶段 0 而不是阶段 5

阶段 5 讲的是**系统性工程**（trace、评测、成本治理）。但这门课讲的是**每一次调用都要有的基本防护**——它和参数一样，是你写第一行调用代码时就要写的东西。

一个扎心的事实：Agent 会放大一切不稳定。单次调用 99% 成功率听起来不错，但一个 10 步的任务，成功率是 `0.99^10 ≈ 90%`；30 步就只剩 74%。**不做好重试与降级，Agent 在长任务上必然失败。**

## 课程结构（约 45–60 分钟）

| 篇目 | 主题 | 你会得到什么 |
|---|---|---|
| C5-1 | 错误全景：状态码与可重试性 | 一张"什么该重试、什么不该"的决策表 |
| C5-2 | 重试策略：退避、jitter 与幂等 | 一套能直接用的重试参数与代码骨架 |
| C5-3 | 限流、并发、超时与降级 | 三级限流模型、降级链、Batch API 场景 |
| C5-4 | 阶段 0 总复习 | 参数速查大表 + 综合自测 + 阶段交付物 |

## 学完你应该能做到

1. 看到任意错误码，立刻判断"重试 / 改参数 / 改输入 / 放弃"；
2. 写出带指数退避 + jitter + 重试预算的调用封装；
3. 设计一个"主模型 → 备模型 → 规则兜底"的降级链；
4. 用 C5-4 的 checklist 自检自己的调用层，然后进入阶段 1。

## 一句话原则

> **失败是常态。**好的 Agent 不是不失败，而是失败后能恢复、能降级、能说清楚为什么失败。
