# 阶段 0 · 模型调用与参数原理
**层级**：阶段（阶段 0 共 6 门课）\\**状态**：进行中 —— C1 已读完，C2 在读；C3–C5 已开课；C0 为后补的前置课\\**规模**：6 门课 / 27 篇正文（另含 6 篇课程索引）\\**时长**：约 5–6 小时，通勤节奏约 12–15 天

## 这一阶段解决什么问题

Agent 的本质是「循环调用模型 + 自己决定下一步」。所以：

> 单次调用里的每一个不确定性，都会被循环放大成系统级问题。

阶段 0 不写 Agent，但把「单次调用」这件事彻底拆干净。六门课各自堵住一个口子：

- **C0 大模型工作原理速成（前置课）**— 堵住「模型内部到底在做什么；token / 向量 / 注意力 / Q K V」；不管会怎样：读 C1、C2 时只能死记结论，无法判断一个说法对不对
- **C1 大模型调用参数与原理**— 堵住「一次调用到底发生了什么；每个参数作用在哪一步」；不管会怎样：同一个 prompt 结果飘忽，无法复现
- **C2 KV Cache 机制与 Agent 上下文复用**— 堵住「为什么缓存的是 K/V；前缀匹配铁律；怎么省钱」；不管会怎样：前缀一变缓存全废，成本翻好几倍
- **C3 Token、分词与成本模型**— 堵住「token 怎么切；怎么数；成本为什么会平方增长」；不管会怎样：Agent 跑几天账单爆掉，还不知道为什么
- **C4 流式输出与结构化输出**— 堵住「SSE 增量解析；工具参数流式拼接；strict 模式」；不管会怎样：工具参数拼错、JSON 解析崩，最难查的 bug
- **C5 稳定性：错误、重试、限流与降级**— 堵住「哪些错能重试；怎么退避；限流与降级链」；不管会怎样：单步 99% 成功率，30 步任务只剩 74%

## 学完你能做到

1. 拿到任何一家模型的 API 文档，能快速判断哪些参数必须管、哪些可以忽略。
2. 在发请求之前就估出这次调用大概多少 token、多少钱、多快返回。
3. 写出一个不会在流式拼接、JSON 解析、报错重试上翻车的调用层。
4. 解释 KV Cache 是什么，以及它为什么决定了 system prompt 该怎么写。
5. 看到 `finish_reason`、`usage`、错误码，知道程序下一步该做什么。
6. 能用自己的话讲清一次推理走了哪几步（分词 → 向量 → 多层 → logits → 采样），并说明 Q / K / V 分别是什么。

## 推荐阅读顺序

第一次学，建议这个顺序（**不是编号顺序**）：

1. **C0**— 模型内部原理。**完全不懂大模型的话先读它**；已经懂 Q/K/V 和注意力的话可以直接跳过。读完再看 C1 和 C2 会轻松很多。
2. **C1**— 先建立「一次调用」的完整画面，后面所有课都往这个画面里填细节。
3. **C3**— 学完立刻能在日常用上，成本意识越早建立越好。
4. **C4**— 动手写代码时同步看，C4-2 工具调用流式拼接是 bug 高发区。
5. **C5**— 边写边查，遇到具体报错再回来翻 C5-1 状态码表。
6. **C2**— 在 C0 基础上深入缓存机制。它解释了 C3 降本手法背后的「为什么」，建议补上（需要先读完 C0-4）。

如果你时间只够两门：**C1 + C3**。若完全没接触过模型原理，再加上**C0-1 + C0-2**（约 20 分钟）。

## 阶段出口标准

以下**6 条**是最低要求，答不上来就先别往前走：

1. 能说清 temperature 和 top_p 分别改变了采样哪一步，以及为什么推理模型不支持它们。
2. 看到 `finish_reason = "tool_calls"` 和 `"length"`，知道程序该怎么分支。
3. 能估算一段中文文本的 token 量级，误差不超过 30%。
4. 能说清为什么「稳定的 system prompt 放前面」能省钱。
5. 能列出 429 和 400 分别该怎么处理（一个重试，一个不重试）。
6. 能解释为什么「缓存只对完全相同的前缀生效」——从 K/V 的生成机制讲起，而不是背规则。
