# C6-2 · 约束 > 角色：为什么「你是资深分析师」没用
> 阅读约 8 分钟。目标：破除「角色扮演」迷信，把力气花在真正有效的约束上。

## 1. 一个广泛流传的误解

很多 prompt 教程教你第一句写：

> 「你是一位拥有 20 年经验的资深数据分析师。」

它的隐含假设是：**给模型贴个身份标签，它就会「表现得更像」那个身份**。

实测结论是：**这类身份描述对输出质量的影响微乎其微，有时甚至略降**（模型可能因为「资深」而倾向于长篇大论、堆砌术语）。真正拉高或拉低质量的，是具体的**约束**和**判断标准**。

## 2. 为什么角色牌不好使

模型没有「自我」可以切换，它只是在**预测下一个 token**（见 C0-1）。「你是一个专家」这条指令，能影响的只是它接下来生成的**语言风格**——比如用词更书面、语气更权威——而**不是**它背后知识和推理的「专业程度」。

换句话说：

- 角色牌改的是**外壳**（语气、口吻）；
- 约束改的是**行为**（该做什么、不该做什么、如何取舍）。

你要的是行为改变，不是语气改变。所以该把 token 花在约束上。

## 3. 什么才是有效的「角色设定」

角色设定不是完全没用，但有效用法是**把身份翻译成可执行的行为约束**。

| 无效写法 | 有效改写 |
|---|---|
| 你是资深律师 | 只引用现行法条，不确定的适用情形要说明争议点 |
| 你是英语母语者 | 输出使用地道的英语表达，避免中式英语，专有名词保持原文 |
| 你是产品经理 | 先复述用户需求，再分「必须 / 可选」两档给出方案 |

看出来了吗：有效版本把「资深」「母语」「产品经理」这些**抽象身份**，翻译成了**具体可验证的行为标准**。模型不需要「理解」身份，只需要照约束执行。

## 4. 例外：角色牌什么时候真的有用

有少数场景，身份标签能带来可观察的差异：

1. **风格 / 口吻要求明确**时（「用小学生能懂的话解释」）——这本质上是「约束」，只是借了角色之名。
2. **领域术语一致性**（「按金融行业惯例叫法」）——避免模型在不同叫法间漂移。
3. **安全 / 合规对齐**（「你是客服，必须遵守以下红线」）——但这同样是把身份转成了规则。

注意这三点里，「角色」都只是「约束」的便捷封装，核心仍然是行为标准。

## 5. 一个可复用的判断句

写 prompt 时，每当你准备写「你是 XX」，先问一句：

> 我把「XX」翻译成一条**可验证的行为约束**了吗？

- 翻译得出来 → 直接写约束，删掉身份牌。
- 翻译不出来 → 说明「XX」本身就没给模型任何信息，留着只是浪费 token。

## 6. 小结

- 「你是 XX」改的是语气，不是能力；模型只在预测 token。
- 把身份翻译成**具体、可验证的行为约束**，才是有效的角色用法。
- 判断句：翻译得出约束就写约束，翻译不出就删。
