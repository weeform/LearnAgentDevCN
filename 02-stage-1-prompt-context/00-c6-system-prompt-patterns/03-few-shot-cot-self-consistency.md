# C6-3 · 少样本、思维链、自一致性：用 token 换效果
> 阅读约 14 分钟。目标：为这三种手法建立「何时用、花多少、值不值」的判断力。

## 1. 三种手法的共同逻辑

少样本（few-shot）、思维链（CoT）、自一致性（self-consistency），本质是同一件事的三种形态：**往 prompt 里多塞 token，换更好的输出**。

- **少样本**：塞「输入输出范例」，让模型照葫芦画瓢。
- **思维链**：塞（或诱导）「推理过程」，让模型先想再答。
- **自一致性**：让模型**想多次**，取多数结果。

它们的成本账都在一条暗线上：**这会增加多少 token**（总纲第 7 节）。用之前先算清这笔账。

## 2. 少样本（few-shot）

**做法**：给 2–5 个「输入 → 期望输出」范例，再接真实输入。

**什么时候有效**：
- 任务**格式敏感**：抽取、分类、改写、命名风格统一。
- 模型对你的「期望输出」没概念，范例是最快的对齐方式。
- 零样本反复调 prompt 调不出来的场景。

**什么时候没用 / 不划算**：
- 任务本身很简单，零样本已经稳定 → 范例是纯开销。
- 范例和真实输入**分布差太远** → 可能误导。
- **范例本身有错** → 模型会忠实学会那个错。范例是「最高优先级的行为示范」，比约束更容易被模仿。

**成本**：范例每次请求都重发。若范例很长，会显著抬高 prompt tokens（且不一定吃满缓存，取决于位置与稳定性）。

**工程技巧**：
- 范例放 **system prompt 末尾或对话靠前位置**，且**内容固定**，才能命中前缀缓存（见 C2-5）。
- 范例宁精勿多：3 个有代表性的 > 10 个同质的。
- 范例要**覆盖边界**，不是覆盖多数。3 个范例里至少留 1 个给「缺字段 / 表述模糊 / 需要拒答」的情况——教模型怎么处理例外，比多教一个正常样例有用。

### 2.1 一个容易踩的坑：范例被「抄」进答案

做「会议纪要 → 待办事项」抽取时，范例里写了「下周一前提交预算表」。真实输入里没有任何时间信息，但模型输出了一个凭空出现的「下周一」。

原因是：**范例里的具体值，会被模型当成「这类输出的默认值」**。修法不是删范例，而是：

- 范例的字段值尽量用 `xxx` 或与业务无关的占位（如「提交周报」），避免带真实日期、人名、金额；
- 在约束里明确「只抽输入中出现的信息，不得补全」；
- 输出加一个 `evidence` 字段，要求摘原文——没有原文可摘的字段自然会被压掉。

## 3. 思维链（Chain-of-Thought）

**做法**：让模型先输出推理步骤，再给最终答案。

**两种形态**（学术上对应 zero-shot CoT / few-shot CoT）：

1. **显式 CoT（zero-shot CoT）**：prompt 里直接要求「先一步步分析，再下结论」，不给范例。
2. **范例 CoT（few-shot CoT）**：few-shot 的范例里带推理过程，模型模仿。

**什么时候有效**：需要**多步推理**的任务——数学、逻辑、多条件判断、需要综合多个事实的结论。典型提升可达数个百分点甚至更多。

**代价与风险**：
- 显式 CoT 会让**输出变长**，推理 token 全部计入 completion（输出最贵，见 C3-3）。
- 推理过程不可控：可能引入错误推理但结论碰巧对，或反之。

**重要边界**：CoT 对**简单任务无益甚至有害**——反而更贵、更慢、还多一分「想歪」的风险。判断标准见 C6-4。

## 4. 自一致性（Self-Consistency）

**做法**：同一个问题让模型**独立推理多次**（用较高的 temperature），对最终答案**投票取多数**。

**逻辑**：单次采样可能踩中某条错误推理路径；多数投票能抵消随机性带来的方差。

**什么时候有效**：答案**离散、有唯一正确解**且推理链较长的任务（数学题、选择题、事实判断题）。

**成本**：**线性放大多倍**——跑 N 次 = 花 N 倍 token。这是三种手法里最贵的。

**工程现实**：生产环境很少直接用「投票」，更多是**多次采样 + 一致性作为质量信号**（不一致说明这题模型吃不准，值得人工介入或换更强模型）。

### 4.1 把「N 倍」算成钱

假设一个判定任务：输入 800 tokens，单次推理输出 600 tokens，模型定价 输入 $3/M、输出 $15/M（数字仅作示例，按你实际账单替换）。

| 方案 | 单次成本 | 对比 |
|---|---|---|
| 单次采样 | 800×3e-6 + 600×15e-6 = $0.0114 | 基准 |
| 自一致性 N=5 | 5 × $0.0114 = $0.057 | **5.0 倍** |
| N=5 + 一次聚合调用 | $0.057 + 少量聚合 ≈ $0.058 | 约 5.1 倍 |

结论很清楚：**自一致性不是「稍微贵一点」，是「按倍数涨」**。所以它只适合两种情况：

1. 单次错误的代价远高于 5 倍调用费（如合规判定、金额计算）；
2. 只对**一小部分难题**开（先用便宜模型判「这题难不难」，难的才跑 N 次）。

要注意一个反直觉的点：**N 从 5 加到 10，收益通常远小于成本翻倍**。多数任务的投票收益在 N=3–5 就趋平，因为错误往往来自同一类系统性偏差（见 C18-2 的「同源错误」），多采几次仍然错在同一个地方。

**代码骨架**（要点是并发 + 只解析最终答案 + 不把推理过程回传）：

```python
from collections import Counter
import asyncio, re

async def one_sample(client, question: str) -> str:
    r = await client.chat(messages=[{"role": "user", "content": question}],
                          temperature=0.8)          # 高温度制造多样性
    return re.search(r"最终答案[:：]\s*(\S+)", r.text).group(1)  # 只取答案

async def self_consistency(client, question: str, n: int = 5):
    answers = await asyncio.gather(*[one_sample(client, question) for _ in range(n)])
    top, count = Counter(answers).most_common(1)[0]
    return {"answer": top, "agreement": count / n}   # agreement 是关键信号
```

`agreement` 比答案本身更有价值：0.8 以上可以放心用，0.4 左右说明模型在这题上没把握——该转人工，或者升级到更强的模型，而不是硬取多数。

## 5. 三种手法的取舍速查

| 手法 | 换什么 | 成本量级 | 典型适用 |
|---|---|---|---|
| 少样本 | 输出对齐 | 低（范例短） | 抽取、分类、改写、风格统一 |
| 思维链 | 推理深度 | 中（输出变长） | 多步推理、综合判断 |
| 自一致性 | 稳定性 | 高（N 倍） | 有唯一解的难题、质量探测 |

三者不是互斥的：常见组合是「少样本定格式 + CoT 定推理深度 + 只对难题开自一致性」，按需叠，别整套上。

## 6. 小结

- 三者都是「用 token 换效果」，用前先算 token 账。
- 少样本治「格式不对齐」，思维链治「推理不够深」，自一致性治「单次不稳」。
- 范例要固定且放稳定位置，才能吃缓存；范例里的具体值会被抄进答案。
- 自一致性是倍数级成本，且 N 加到 5 以上收益趋平；`agreement` 比答案更有用。
