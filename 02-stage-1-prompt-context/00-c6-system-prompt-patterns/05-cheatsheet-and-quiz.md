# C6-5 · System Prompt 工程速查表与自测
> 阅读约 12 分钟。这一篇把 C6 压成能查、能自测的东西。

## 1. 五段式模板速查

| 段 | 回答 | 权重 | 要不要写 |
|---|---|---|---|
| 角色 | 你是谁 | 低 | 可省，除非翻译成约束 |
| 目标 | 要做什么 | 中 | 一句话即可 |
| 约束 | 不能 / 必须怎么做 | **最高** | 几乎必写，要具体可验证 |
| 输出格式 | 结果长什么样 | 高 | 能用 Schema/工具就别用散文 |
| 示例 | 长什么样才算对 | 高（格式敏感任务） | 按需，2–5 个，固定放稳定位 |

## 2. 三条纪律

1. 约束要**具体、可验证**（「回答不超过 100 字」>「不要废话」）。
2. 格式优先走**结构化手段**（`response_format` / 工具），别只喊「只输出 JSON」。
3. prompt 要**版本化**，改动记「为什么改、改哪了」。

## 3. 三种手法取舍

| 手法 | 换什么 | 成本 | 典型适用 |
|---|---|---|---|
| 少样本 | 输出对齐 | 低 | 抽取 / 分类 / 改写 / 风格 |
| 思维链 | 推理深度 | 中 | 多步推理、综合判断 |
| 自一致性 | 稳定性 | 高（N 倍） | 有唯一解的难题 |

## 4. 症状 → 病灶对照表

调 prompt 时最耗时间的不是写，是**不知道问题出在哪，于是乱改**。这张表用来定位：

| 你观察到的症状 | 大概率病灶 | 该改哪里 |
|---|---|---|
| 输出格式时好时坏，JSON 经常解析失败 | 只靠 prompt 喊格式，没上结构化输出 | 换 `response_format` / 工具，别继续调措辞 |
| 编造数据里没有的内容 | 缺反幻觉约束；或上了 CoT 逼它"分析" | 加「只依据输入 + 必须有 evidence」，去掉 CoT |
| 输出又长又空，全是套话 | 角色牌太重（"资深专家"）；缺长度约束 | 删角色句，加字数上限与禁用词 |
| 简单任务也答错，且答案绕 | 对简单任务上了 CoT | 删掉「先分析」，直接问 |
| 该拒答的时候硬答 | 没有兜底口径 | 明确「不知道」是合法答案，并规定怎么表达 |
| 同样输入两次结果差很多 | temperature 过高 / 缺格式约束 | 判定类任务降到 0–0.3；加结构约束 |
| 改了一堆，效果没变 | 改的都是低权重段（角色、目标） | 回到约束与输出格式，一次只改一处 |
| 之前好好的，突然变差 | 模型版本变了 / prompt 被改过没记 | 查 prompt 版本号与模型版本，跑回归集 |

用法：**从上往下扫，命中症状就先改那一格，别一次改五处**。一次只改一处，才知道是谁起的作用。

## 5. 上线前自检清单

写完 system prompt，交付前过一遍。全部能打勾才发：

- [ ] 约束每一条都能配出一个「违反样例」（配不出的删掉）
- [ ] 输出格式有 Schema 或工具兜底，不依赖模型自觉
- [ ] 示例不超过 5 个，内容固定，且不含真实人名 / 日期 / 金额
- [ ] 明确了「不知道」「数据不足」怎么说，而不是留给模型自由发挥
- [ ] 版本号写在 prompt 顶部，含日期与变更原因
- [ ] 有 ≥20 条回归集，改动能跑一遍对比
- [ ] 算过这个 prompt 的固定开销（system + 示例 tokens × 日调用量）

最后一条经常被忽略：一个 800 tokens 的 system prompt，配 5 个范例可能到 2000 tokens；日调用 10 万次的话，**固定开销本身就是主要成本**，而且这部分与任务难度无关。范例该不该留，得先看这笔账。

## 6. 自测（10 道）

> 答对 7 道以上，可以进入 C7。

1. 五段式模板是哪五段？哪一段权重最高？
2. 为什么「你是资深分析师」这类角色牌对输出质量影响很小？
3. 把「你是资深律师」翻译成一条可验证的行为约束。
4. 怎么判断一条约束算不算「可验证」？给一个检验方法。
5. 少样本的范例应该放在哪里、保持什么状态？为什么？
6. 范例里的具体值可能带来什么副作用？怎么防？
7. 自一致性为什么是三种手法里最贵的？N 从 5 加到 10 值不值？
8. 举两个「CoT 反而更差」的场景，并说明硬判据是什么。
9. 抽取类任务上 CoT，最典型的错误形态是什么？
10. 一个 prompt 同时用到「反幻觉约束 + 结构化输出 + 兜底」，这叫什么思路？怎么判断某一段该不该留？

### 答案要点

1. 角色 / 目标 / 约束 / 输出格式 / 示例；约束权重最高。
2. 模型只在预测 token，身份牌只改语气不改能力；真正有效的是把身份翻译成行为约束。
3. 「只引用现行法条，不确定的适用情形要说明争议点」这类可验证标准。
4. 给每条约束配一个「违反样例」；配不出来说明它空泛到无法判定，应删。
5. 放 system prompt 末尾或对话靠前、内容固定，才能命中前缀缓存（见 C2-5）。
6. 范例里的真实日期 / 金额会被当成默认值抄进答案；改用占位值 + 要求 evidence 摘原文。
7. 需要把同一问题独立采样 N 次再投票，token 线性放大 N 倍；N=3–5 后收益趋平，加到 10 通常是浪费。
8. 简单任务、创造性/发散任务（另可举「有结构化替代」「推理模型」）；判据是中间步骤能否被验算。
9. 模型为了「填满分析过程」而补全输入里没有的字段（如凭空给金额），`null` 变成编造值。
10. 模式组合（组合优于单点）；判断方法是反推「删掉这段输出会变成什么样」，答不上来就该删。
