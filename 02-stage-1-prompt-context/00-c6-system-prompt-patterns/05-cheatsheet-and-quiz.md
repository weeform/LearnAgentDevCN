# C6-5 · System Prompt 工程速查表与自测
> 阅读约 10 分钟。这一篇把 C6 压成能查、能自测的东西。

## 1. 五段式模板速查

| 段 | 回答 | 权重 | 要不要写 |
|---|---|---|---|
| 角色 | 你是谁 | 低 | 可省，除非翻译成约束 |
| 目标 | 要做什么 | 中 | 一句话即可 |
| 约束 | 不能 / 必须怎么做 | **最高** | 几乎必写，要具体可验证 |
| 输出格式 | 结果长什么样 | 高 | 能用 Schema/工具就别用散文 |
| 示例 | 长什么样才算对 | 高（格式敏感任务） | 按需，2–5 个，固定放稳定位 |

## 2. 三条纪律

1. 约束要**具体、可验证**（「回答不超过 100 字」>「不要废话」）。
2. 格式优先走**结构化手段**（`response_format` / 工具），别只喊「只输出 JSON」。
3. prompt 要**版本化**，改动记「为什么改、改哪了」。

## 3. 三种手法取舍

| 手法 | 换什么 | 成本 | 典型适用 |
|---|---|---|---|
| 少样本 | 输出对齐 | 低 | 抽取 / 分类 / 改写 / 风格 |
| 思维链 | 推理深度 | 中 | 多步推理、综合判断 |
| 自一致性 | 稳定性 | 高（N 倍） | 有唯一解的难题 |

## 4. 自测（8 道）

> 答对 6 道以上，可以进入 C7。

1. 五段式模板是哪五段？哪一段权重最高？
2. 为什么「你是资深分析师」这类角色牌对输出质量影响很小？
3. 把「你是资深律师」翻译成一条可验证的行为约束。
4. 少样本的范例应该放在哪里、保持什么状态？为什么？
5. 自一致性为什么是三种手法里最贵的？
6. 举两个「CoT 反而更差」的场景。
7. 抽取类任务为什么不该上 CoT？
8. 一个 prompt 同时用到「反幻觉约束 + 结构化输出 + 兜底」，这叫什么思路？

### 答案要点

1. 角色 / 目标 / 约束 / 输出格式 / 示例；约束权重最高。
2. 模型只在预测 token，身份牌只改语气不改能力；真正有效的是把身份翻译成行为约束。
3. 「只引用现行法条，不确定的适用情形要说明争议点」这类可验证标准。
4. 放 system prompt 末尾或对话靠前、内容固定，才能命中前缀缓存（见 C2-5）。
5. 需要把同一问题独立采样 N 次再投票，token 线性放大 N 倍。
6. 简单任务、创造性/发散任务（任举两个，另可举「有结构化替代」「推理模型」）。
7. 抽取要「忠实」不要「推理」，CoT 的自由联想会引入脑补，是风险不是收益。
8. 模式组合（组合优于单点）。
