# C8-3 · 防御清单：白名单、权限与人工确认
> 阅读约 10 分钟。目标：落地一份「即使被注入也做不了坏事」的权限层防御清单。

## 1. 为什么权限层才是真正的底线

C8-2 讲过：prompt 技巧堵不死注入。那安全的真正来源是什么？答案是——**让模型即使被诱导，也没有能力造成伤害**。

这属于「最小权限」（least privilege）原则：给 Agent 的能力，恰好够它完成任务，多一分都不给。

## 2. 工具调用白名单

**做法**：把工具分成「安全 / 敏感」两类，敏感工具不直接对模型开放。

| 类别 | 例子 | 处理 |
|---|---|---|
| 安全（只读） | 查库、检索、计算 | 直接开放给模型 |
| 敏感（有副作用） | 发邮件、下单、删数据、转账 | 默认**不暴露**，或走人工确认 |

关键动作：**从工具列表的源头就控制**——模型只能调用「你放进 tools 数组」的工具。一个危险工具根本不放进上下文，模型连「尝试调用」的机会都没有。这是最可靠的一条。

## 3. 敏感操作人工确认（HITL）

对「必须暴露、但有副作用」的操作，加一道**人工闸门**：

- 模型输出「意图」→ **暂停，等人类批准** → 才真正执行。
- 典型实现：`tool_choice` 强制模型先调一个 `request_approval` 工具，人点了「同意」，副作用工具才被调用（见 C1-4 的 tool_choice 用法）。

这条把「模型自主行动」变成「模型建议 + 人拍板」，是最直接的风险闸门。

## 4. 参数白名单与校验

即便模型能调某工具，也要**限制它传什么参数**：

- 金额、收件人、URL 这类关键参数，在**代码层**二次校验（范围、白名单、格式），不能只信模型的输出。
- 例如「发邮件」工具：收件人必须是通讯录白名单内的地址，正文里的外链一律剥离。

## 5. 输出过滤

模型输出进入下一环节（展示给用户、发给第三方、执行）前，做检查：

- 是否包含**要泄露的敏感信息**（内部密钥、他人隐私、对话历史）。
- 是否包含**可疑外链 / 指令片段**。

这是「事后兜底」，不能替代前面几层，但能拦住一部分漏网之鱼。它的边界是：**只能拦「已知模式」**——对从未见过的新泄露方式、绕过规则的对抗样本，规则过滤往往失效，所以不能把它当成最后防线。

## 6. 一份可落地的防御清单

- [ ] 危险工具（副作用）默认不暴露给模型
- [ ] 敏感工具走人工确认（HITL）闸门
- [ ] 关键参数在代码层二次校验（白名单 / 范围 / 格式）
- [ ] 外部内容做隔离标记 + 「视为数据」声明（C8-2）
- [ ] 外部内容入口做基础清洗（去控制字符、限长）
- [ ] 模型输出经「敏感信息 / 外链」过滤后再流出
- [ ] 记录完整的 trace 与工具调用日志（便于事后审计，见阶段 5）

## 7. 小结

- 最小权限：给 Agent 的能力恰好够用，多一分都不给。
- 白名单（工具 / 参数）+ 人工确认 + 输出过滤，是真正的安全底线。
- prompt 防御降噪，权限层兜底，两者缺一不可。
