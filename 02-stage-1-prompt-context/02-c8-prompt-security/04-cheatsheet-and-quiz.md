# C8-4 · 提示词安全速查与自测
> 阅读约 8 分钟。这一篇把 C8 压成能查、能自测的东西。

## 1. 注入分类速查

| 类型 | 攻击者位置 | 目标 | 防御难度 |
|---|---|---|---|
| 直接注入 | 与模型对话的人 | 套 system prompt、绕过规则 | 易（可见、可过滤） |
| 间接注入 | 藏在数据/网页/邮件里 | 数据泄露、越权、输出污染 | 难（Agent 特有风险） |

根因：模型分不清「数据」和「指令」，防御 = 人为划信任边界。

## 2. 三层防御

| 层 | 手段 | 作用 |
|---|---|---|
| 入口层 | 数据清洗、去控制字符、限长 | 降噪 |
| 上下文层 | 隔离标记 + 「视为数据」声明 | 划边界、提成本 |
| 权限层 | 工具白名单、人工确认、输出过滤 | **真正的兜底** |

## 3. 自测（6 道）

> 答对 4 道以上，本课通过。

1. 提示词注入和越狱（jailbreak）的区别是什么？
2. 为什么间接注入是 Agent 的特有风险？
3. 隔离标记 + 「视为数据」声明，为什么只能「降噪」不能「彻底防御」？
4. 为什么「危险工具不放进 tools 数组」是最可靠的白名单手段？
5. 什么操作需要加「人工确认」闸门？举两个例子。
6. 输出过滤拦不住什么？它应该被放在防御的什么位置？

### 答案要点

1. 越狱是绕过安全对齐；注入是利用模型的指令遵循，让攻击者内容被当成指令执行。
2. Agent 会主动读外部内容并据此行动，攻击面比不读外部内容的聊天助手大得多。
3. 隔离标记本身也是上下文里的 token，攻击者能模仿标记提前闭合，对抗会升级；所以它只能提高成本、不能绝对阻断。
4. 模型只能调用放进 tools 的工具，根本不放进去，模型连尝试的机会都没有。
5. 有副作用、不可逆的操作：发邮件、下单、转账、删数据（任举两个）。
6. 拦不住「新出现、未识别」的泄露模式；它是事后兜底，不能替代白名单和权限层。
