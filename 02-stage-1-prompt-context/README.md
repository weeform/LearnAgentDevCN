# 阶段 1 · Prompt 与上下文工程
**层级**：阶段（阶段 1 共 3 门课）
**规模**：3 门课 / 13 篇正文（另含 3 篇课程索引）
**时长**：约 2.5–3.5 小时
**前置**：阶段 0（模型调用与参数原理）
**产出**：一套可复用的 system prompt 模板 + 一套明确的上下文裁剪策略

## 这个阶段解决什么问题

阶段 0 把「单次调用」拆干净了。但同一个模型、同一份数据，换个 prompt 写法，效果可能差一个量级——差距往往不在模型能力，而在你怎么跟它说话。

这一阶段把「写 prompt」从玄学变成工程动作，核心是承认一个约束：

> 上下文是有限资源，而你想塞进去的东西永远不够放。

所以阶段 1 的两条主线是：**怎么把指令说清楚**（C6、C8），**怎么在有限空间里做取舍**（C7）。

## 学完你能做到

1. 写出结构化的 system prompt（角色 / 目标 / 约束 / 输出格式 / 示例），而不是一段想到哪写到哪的散文。
2. 判断什么场景值得上少样本、思维链、自一致性，以及各自要付多少 token。
3. 在上下文不够时做有依据的取舍：留什么、压缩什么、什么时候该摘要。
4. 识别提示词注入（尤其是 RAG 文档里藏指令这种间接注入），并做基本防御。
5. 把 prompt 当代码管：版本化、可测试、能回归。

## 推荐阅读顺序

1. **C6**— 先建立「怎么写 prompt」的骨架，后面所有手法都长在这副骨架上。
2. **C7**— 上下文管理的取舍逻辑依赖 C2（KV Cache），若阶段 0 跳过 C2 建议先补 C2-5。
3. **C8**— 安全课相对独立，但它的防御手段（隔离标记、白名单）会和 C7 的上下文装配交叉，放最后读更顺。

## 阶段出口标准

做完这三件事再进阶段 2：

1. **一套 system prompt 模板**：至少能覆盖「问答」「抽取」「改写」三类任务，带版本号。
2. **一个上下文裁剪策略**：有明确规则（例如「工具返回超过 N token 就摘要，原始结果落盘存引用」），不是「砍掉最老的几条」。
3. **一份注入防御清单**：至少覆盖「外部内容隔离标记」「工具调用白名单」「敏感操作需确认」三条。
