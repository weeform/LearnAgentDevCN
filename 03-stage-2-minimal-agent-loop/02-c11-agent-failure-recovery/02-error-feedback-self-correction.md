# C11-2 · 错误回传与自我修正
> 阅读约 12 分钟。目标：掌握「把报错喂回模型 → 让它自己改」的完整套路，以及它的边界。

## 1. 一个直觉上会做错的选择

工具执行失败时，新手最常见的两个处理：

- **`try/except` 里 `raise`**：异常往上抛，整个循环崩掉，任务中断。
- **`except: pass` 吞掉**：循环继续，但模型**不知道失败了**，会在错误的基础上脑补。

两者都错。正确的做法是**第三条路**：

> 把错误**结构化地回传**给模型，让它「看到失败、自己修正」。

## 2. 回传什么：结构化的错误对象

回传的错误要**清晰、可行动**，别丢一句「出错了」：

```python
return {
    "success": False,
    "error": "amount 必须在 1 到 10000 之间，收到 -5",
    "hint": "请把 amount 改为 1~10000 之间的正数后重试",
}
```

要素：
1. **失败状态**：明确标注 `success: False`，别让模型猜。
2. **错误内容**：具体、带上下文（哪个参数、收到什么值、期望什么）。
3. **可行动的提示**：告诉模型「怎么改」。

> 说明：C9-3、C10-3 里的最小实现只返回 `{"error": ...}`，是为了让示例尽量短。生产里建议**统一为 `{success, error, hint}` 三字段**（成功时 `success: True`），这样调用方不用靠「有没有 error 字段」来猜成败。

## 3. 回传之后：模型真的会修吗

多数情况下会。模型看到错误 + 提示，下一轮会**换个参数 / 换个工具**重试。这是 Agent 相对「一次性调用」的核心优势——**它有机会在失败后自我纠正**。

但有一个边界要清醒：

> 自我修正**不是万能**。同一个错误反复出现 2–3 次还没修好，说明模型「不会了」，继续重试只是烧钱。此时该**主动终止 + 降级**（换更强模型、走人工、给兜底答案）。

## 4. 一个可落地的策略：有限次修正

```
for attempt in range(MAX_RETRY):
    result = execute(name, args)          # result 是 dict
    if result.get("success"):
        break
    messages.append(tool_error(result))   # 回传错误
    # 模型下一轮据此重新决策

if still_failing:
    # 降级：换模型 / 转人工 / 兜底话术
    return fallback()
```

要点：
- **修正有次数上限**，不是无限重试。
- 修正次数和「最大步数」（C11-3）要**分开记账**，否则逻辑会缠在一起。

## 5. 哪些错误「值得回传让模型修」

| 错误 | 回传让模型修？ | 说明 |
|---|---|---|
| 参数越界 / 格式错 | ✅ | 模型改参数就能修 |
| 用错了工具 | ✅ | 模型换工具就能修 |
| 工具代码自身 bug | ❌ | 模型修不了，该修代码 |
| 权限不足 / 资源不存在 | ⚠️ | 视情况：可回传「换个对象」 |

判断标准一句话：**「这个错误，模型改它的行为就能解决吗？」能，就回传；不能，就降级。**

## 6. 小结

- 报错别 `raise`（崩掉）、别吞掉（脑补），要**结构化回传**。
- 回传要素：具体错误 + 可行动提示 + 失败状态。
- 自我修正有边界：反复修不好就终止 + 降级。
- 判断标准：模型改行为能否解决？能→回传，不能→降级。
