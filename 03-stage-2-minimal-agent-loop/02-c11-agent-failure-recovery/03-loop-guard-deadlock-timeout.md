# C11-3 · 步数 / 死循环 / 超时：三道保险
> 阅读约 12 分钟。目标：为 Agent 循环装上「不失控」的三道保险。

## 1. 第一道：最大步数（硬上限）

`MAX_STEPS` 是**物理层面的兜底**——无论模型多想继续，步数一到就强制停。这在 C9-4 讲过，这里补它的「记账」细节：

```python
MAX_STEPS = 12

for step in range(MAX_STEPS):
    ...
    if step == MAX_STEPS - 1:
        # 最后一步：禁止再调工具，强制收口
        resp = create(..., tool_choice="none")
```

**技巧**：最后一步把 `tool_choice` 设成 `"none"`（见 C1-4），**强制模型给最终答案**，而不是又调一轮工具后被硬截断。这能把「步数用尽」从「失败」变成「一次尽量正常的收尾」。

## 2. 第二道：死循环检测

最大步数能兜住「无限循环」，但「死循环」更隐蔽——模型在**几步之间来回打转**，步数还没到上限，但**没有实质进展**。

检测信号（出现任一条，警惕）：

| 信号 | 例子 |
|---|---|
| 重复调用同一工具 + 相同参数 | 连续 3 次 `search_weather("北京")` |
| 历史片段重复 | 最近 2 轮和更早的 2 轮完全相同 |
| 步数增加但任务无进展 | 一直在「思考」，从不产出结果 |

**应对**：
1. **记录最近 N 步的动作签名**（工具名 + 参数），重复超过阈值就打断。

```python
seen = {}
for step in range(MAX_STEPS):
    ...
    sig = json.dumps(msg.tool_calls, ensure_ascii=False, sort_keys=True)  # 本轮动作签名
    seen[sig] = seen.get(sig, 0) + 1
    if seen[sig] >= 3:                        # 同一动作重复 3 次 = 原地打转
        messages.append({"role": "user",
                         "content": "你似乎在重复同样的操作，请换个思路，或给出当前能给出的最佳答案。"})
```

2. 打断后**回传一个提示**（如上）：「你似乎在重复同样的操作，请换个思路，或给出当前能给出的最佳答案。」
3. 若仍无进展，**终止 + 降级**。

## 3. 第三道：超时处理

Agent 会卡在**网络、限流、长任务**上。超时要分层设（阶段 0 的 C5-3 已给框架，这里落到 Agent 场景）：

| 层 | 超时 | 动作 |
|---|---|---|
| 连接 | 几秒 | 重试 |
| 首 token | 十几秒 | 重试 / 换备模型 |
| 单步整体 | 30–60 秒 | 回传「超时」给模型，让它换个做法 |
| 全任务 | 分钟级 | 整体降级 / 转人工 |

**单步超时的特殊处理**：不要直接 `raise`，而是**回传一个「工具超时」的结果**，让模型决定是重试、换工具还是放弃——和 C11-2 的错误回传是同一思路。

## 4. 三道保险的分工

| 保险 | 防什么 | 触发后 |
|---|---|---|
| 最大步数 | 无限循环 | 强制收口（tool_choice=none） |
| 死循环检测 | 原地打转 | 打断 + 提示换思路 |
| 超时 | 卡住无响应 | 回传超时 / 降级 |

它们**不互相替代**：最大步数兜总量，死循环检测兜「假进展」，超时兜「不响应」。三个一起，循环才「活得下来」。

## 5. 小结

- 最大步数：硬上限，末步 `tool_choice=none` 强制收口。
- 死循环检测：记录动作签名，重复就打断 + 提示。
- 超时：分层设，单步超时回传让模型决策，别直接崩。
