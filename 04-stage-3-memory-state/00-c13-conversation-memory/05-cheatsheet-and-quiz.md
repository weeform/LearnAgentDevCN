# C13-5 · 速查表与自测
> 阅读约 10 分钟。目标：把 C13 的核心结论固化成一页，并用自测检验。

## 速查表

### 四种消息角色怎么处理

| 角色 | 处理 |
|---|---|
| `system` | 保持稳定，别动（动就碎缓存） |
| `user` | 明确要求记住的，逐字保留 |
| `assistant` | 已完成可摘要，未完成目标要保留 |
| `tool` | 预算黑洞，单独处理（截断/抽取/落盘+引用/分页） |

### 压缩三法分界

| 操作 | 判据 |
|---|---|
| **保留原文** | 删掉它任务就不能正确完成 |
| **摘要** | 过程已完成、结论还有用 |
| **删除** | 重复、失效、不影响后续 |

### 工具返回四手法

| 手法 | 适用 |
|---|---|
| 截断 | 关键信息在前面 |
| 字段抽取 | 结构化 JSON，字段已知 |
| 落盘+引用 | 大结果、可能二次使用（最推荐） |
| 分页 | 结果巨大需浏览 |

### 压缩及格线

- token 降幅 ≥ 40%，成功率下降 ≤ 5%。
- 两个指标成对看，用固定评测集跑「基线 vs 压缩」。

## 自测题

1. 为什么说「短期记忆 = 消息数组」？它和「模型记住了」的区别是什么？
2. 用户在第 1 轮说「这次汇报用 PPT 不用 Word」，任务跑到第 20 轮要压缩。这句话该删、该摘要、还是保留？为什么？
3. 一个查库工具一次返回 8000 行，你打算怎么处理？写出你的方案和理由。
4. 你的压缩策略让 token 降了 60%，但任务成功率从 90% 掉到 70%。问题最可能出在哪？怎么排查？
5. 为什么摘要调用要固定 `temperature=0`？

## 参考答案要点

1. 模型无状态，每轮从零开始；「记忆」靠每轮重发历史。所以短期记忆就是消息数组，不是模型内部状态。
2. 保留原文——这是用户偏好，属于「删掉就不能正确完成」的必须保留项；即使它出现在最早期，也不能按时间顺序删。
3. 落盘+引用：结果存文件，上下文只放 total + 前几行 + 句柄，模型需要时按 hint 用 `read_file` 分页读。理由：不丢信息、不爆上下文。
4. 最可能删了必须保留的内容（用户偏好/未完成承诺），或摘要把结论压掉了，或工具返回压太狠且模型不会回读。按 C13-4 第 5 节顺序排查。
5. 保证可复现（三条暗线之二）：同一历史每次压出同样结果，否则任务结果不可复现。
