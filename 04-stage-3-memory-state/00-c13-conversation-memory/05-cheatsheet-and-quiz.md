# C13-5 · 速查表与自测
> 阅读约 12 分钟。目标：把 C13 的核心结论固化成一页，并用自测检验。

## 1. 四种消息角色怎么处理

| 角色 | 处理 |
|---|---|
| `system` | 保持稳定，别动（动就碎缓存） |
| `user` | 明确要求记住的，逐字保留 |
| `assistant` | 已完成可摘要，未完成目标要保留 |
| `tool` | 预算黑洞，单独处理（截断/抽取/落盘+引用/分页） |

## 2. 压缩三法分界

| 操作 | 判据 |
|---|---|
| **保留原文** | 删掉它任务就不能正确完成 |
| **摘要** | 过程已完成、结论还有用 |
| **删除** | 重复、失效、不影响后续 |

## 3. 工具返回四手法

| 手法 | 适用 |
|---|---|
| 截断 | 关键信息在前面 |
| 字段抽取 | 结构化 JSON，字段已知 |
| 落盘+引用 | 大结果、可能二次使用（最推荐） |
| 分页 | 结果巨大需浏览 |

## 4. 压缩及格线

- token 降幅 ≥ 40%，成功率下降 ≤ 5%。
- 两个指标成对看，用固定评测集跑「基线 vs 压缩」。

## 5. 内容类型 → 操作速查

拿到一条消息，按这张表直接定去处，不用每次重新纠结：

| 内容 | 操作 | 备注 |
|---|---|---|
| 任务目标、用户明确的偏好 | **提到数组外**，写进变量 | 最有效的一招，永远不被裁 |
| 安全约束（别做危险操作） | 保留（本应在 system） | 若出现在 user 里，移到 system |
| 用户原话中的关键数字/ID/日期 | 逐字保留 | 不能概括，只能照抄 |
| 已完成的工具返回 | 摘要成结论 | 保留结论，删过程 |
| 失败尝试 | 压成负向约束一行 | 不能整删，否则重复踩坑 |
| 重复的寒暄、确认语 | 删除 | 零信息量 |
| 被更新过的旧值 | 删除 | 只留最新值 |
| 模型的过程性思考 | 摘要 | 结论留，推理删 |

这张表里第一行值得单独强调：**「把目标提到数组外」比任何裁剪算法都有用**。它在数组里就是一个随时可能被裁的受害者；它单独存在一个变量里，每次装配时无条件塞回去，就不可能丢。

## 6. 两个硬约束（容易踩）

1. **`tool_calls` 与 `tool` 消息必须成对**。裁剪的最小单位是「一整组 assistant(tool_calls) + tool(...)」，拆开会导致 API 报错。裁剪后跑一次孤儿检查。
2. **一轮对话 ≠ 一条消息**。一次用户请求可能产生 5–6 条消息，压缩单位应是"完整调用链"，不是"一条"。

## 7. 自测题（7 道）

> 答对 5 道以上，本课通过。

1. 为什么说「短期记忆 = 消息数组」？它和「模型记住了」的区别是什么？
2. 用户在第 1 轮说「这次汇报用 PPT 不用 Word」，任务跑到第 20 轮要压缩。这句话该删、该摘要、还是保留？为什么？
3. 裁剪消息时，为什么不能只删掉那条很大的 `tool` 消息？
4. 一个查库工具一次返回 8000 行，你打算怎么处理？写出你的方案和理由。
5. 你的压缩策略让 token 降了 60%，但任务成功率从 90% 掉到 70%。问题最可能出在哪？怎么排查？
6. 为什么摘要调用要固定 `temperature=0`？
7. 你做了「落盘 + 引用 + hint」，评测显示信息没丢，但成功率还是降了。最可能的原因是什么？怎么验证？

## 8. 参考答案要点

1. 模型无状态，每轮从零开始；「记忆」靠每轮重发历史。所以短期记忆就是消息数组，不是模型内部状态。
2. 保留原文——这是用户偏好，属于「删掉就不能正确完成」的必须保留项；即使它出现在最早期，也不能按时间顺序删。更好的做法是把它提到数组之外。
3. `assistant` 的 `tool_calls` 必须有对应 `tool_call_id` 的 `tool` 消息，删除后数组结构非法，API 会直接拒绝。裁剪最小单位是整组。
4. 落盘+引用：结果存文件，上下文只放 `total` + 前几行 + 句柄，模型需要时按 hint 用 `read_file` 分页读。理由：不丢信息、不爆上下文。注意前几行要给聚合值并声明"仅是样例"。
5. 最可能删了必须保留的内容（用户偏好/未完成承诺），或摘要把结论压掉了，或工具返回压太狠且模型不会回读。按 C13-4 第 5 节顺序排查，并先跑一次"不压缩基线"排除非压缩原因。
6. 保证可复现（三条暗线之二）：同一历史每次压出同样结果，否则任务结果不可复现。
7. 模型根本没去调取回工具（`read_file` 调用次数为 0），直接基于样例编答案。验证方法：统计压缩后 `read_file` 的调用次数，并检查 hint 措辞与工具是否在 tools 列表里。
