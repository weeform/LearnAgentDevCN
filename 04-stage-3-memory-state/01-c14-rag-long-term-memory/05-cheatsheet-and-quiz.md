# C14-5 · 速查表与自测
> 阅读约 12 分钟。目标：把 C14 全链路固化成一页，并用自测检验。

## 1. 长上下文 vs RAG 决策

| 情况 | 选 |
|---|---|
| 有界文档、需整体推理 | 长上下文 |
| 海量内容、只定位片段 | RAG |
| 内容多又要综合 | 混合式（RAG 检索 + 长上下文合成） |
| 内容小、每次能全塞 | 直接塞，别上 RAG |
| 答案在某个字段里 | **先查数据库，别上 RAG** |

## 2. RAG 链路五环

| 环节 | 要点 |
|---|---|
| 切分 | 结构+段落，块 300–800 token，边界贴合完整意思 |
| Embedding | 看语言/维度/长度/价格；别拿生成模型当 Embedding |
| 检索 | 混合（向量+关键词），精准取 5–10、合成取 20–40 |
| 重排 | 交叉编码器只重排 top 50–100，取最终 top 5–20 |
| 维护 | 去重、过期、矛盾（新覆盖旧+标注来源时间）、污染 |

## 3. 记忆维护四件套

去重（相似度阈值合并）、过期（时间戳清理）、矛盾（新覆盖旧 + 显式冲突）、污染（准入校验 + 可信度标注）。

## 4. 症状 → 环节对照

RAG 出问题最难的是定位，因为最终表现都是"答错了"。按这张表往下切：

| 症状 | 最可能的环节 | 怎么验证 |
|---|---|---|
| 答案总是"通用常识"，不提文档内容 | 检索没召回 | 看 top-50 里有没有 gold chunk |
| 答案对一半、漏条件 | 切分把条件与结论拆开了 | 看 gold chunk 的边界 |
| 答案引用了过期政策 | 记忆没做时效维护 | 查是否有多版本共存 |
| 同样的问题两次答案不同 | 矛盾记忆共存 / temperature 高 | 查库里是否有冲突条目 |
| 数字看起来合理但对不上 | 检索到了相似但不对的块 | 看 Precision@k |
| 正确答案在库里却永远搜不到 | Embedding 静默截断 / 权限过滤挡掉 | 打印入库 token 数、检查 filter |
| 召回好但答案差 | 排序问题（相关块排太后） | 算 MRR，上 rerank |

这张表的用法：**先区分"没捞到"还是"捞到了没用对"**。前者查切分/Embedding/过滤，后者查排序/上下文装配。两类问题的修法完全不同，混着调只会浪费时间。

## 5. 关键数字速记

| 项 | 起点值 | 依据 |
|---|---|---|
| 块大小 | 300–800 token | 通用文本经验区间 |
| 初检索 k | 50（单路），合并后 100 | 给 rerank 留余量 |
| rerank 输入 | top 50–100 | 全库重排太贵 |
| 最终进上下文 | 5–10（问答）/ 20–40（合成） | 按任务类型 |
| RRF 的 k | 60 | 原论文经验值 |
| 去重阈值 | >0.95 合并，0.85–0.95 标记 | 避免误合并 |
| 评测集规模 | 50–100 条 | 够看出趋势，不必上千 |

## 6. 自测题（8 道）

> 答对 6 道以上，本课通过。

1. 一个 3 页的产品说明文档，每次都能完整放进窗口。要不要上 RAG？为什么？
2. 用户问「订单 A-1024 退款到账了吗」，你的 RAG 召回了《退款政策说明》并据此回答。问题出在哪？
3. 用户知识库里既有「自然语言的产品介绍」，又有「精确的型号编号」。纯向量检索会出什么问题？怎么解决？
4. 你的检索召回率很高（正确答案总在 top-50 里），但模型还是经常答错。最可能是什么环节出问题？
5. 用户换了新的退货政策，但旧政策还在知识库里被检索到。这属于哪类记忆问题？怎么处理？
6. 「切分」为什么不能按固定字符数硬切？举一个具体被破坏的例子。
7. 去重阈值定得太低（比如 0.8 就合并）会有什么后果？怎么缓解？
8. RRF 里 `k=60` 起什么作用？为什么不用「简单去重后拼接」？

## 7. 参考答案要点

1. 不上。每次能全塞且不超预算，直接塞即可，搭 RAG 是过度设计（见 C14-1 决策表）。
2. 选错了数据源：答案是订单表里的一个字段，该用结构化查询而不是文本检索；检索到的政策只是"一般规则"，不等于"这笔订单的状态"。
3. 向量检索不懂精确匹配，可能漏掉含型号的那段。用混合检索（向量 + BM25），RRF 融合后重排。
4. 很可能是「排序」问题而非「召回」问题——召回够但排错位置。加 rerank，把最相关的排前面；也可能是装配时把相关块放在了中段。
5. 属于「过期 + 矛盾」记忆。做法：每条记忆带时间戳，新政策写入时把旧政策标记 `superseded_by`；但要先确认两者适用条件是否相同（不同地区可能并行有效）。
6. 会拆散表格（表头与数据行分离）、把"条件+结论"分开（如"满 10 年多 5 天"与"不适用试用期"）、把总述与条目分开；块边界应贴合"完整意思"。
7. 会把不同记忆误合并（如"退货 7 天"和"退货 15 天"），**直接丢信息**，比重复更糟。缓解：留 0.85–0.95 的"疑似同族"档，只在检索时去重，不做不可逆合并。
8. `k` 压平头部差距，使"两路都靠前"优于"单路第一"；简单拼接会让某一路的第 1 名独占鳌头，浪费另一路的信号。
