# C15-5 · 阶段 3 总复习与自测
> 阅读约 12 分钟。目标：把阶段 3 的三类记忆串成一张图，对照出口标准做综合自测。

## 一、阶段 3 串讲

Agent 跑长任务撞三堵墙，对应三类机制：

| 墙 | 机制 | 课程 | 核心手法 |
|---|---|---|---|
| 上下文会爆 | **短期记忆** | C13 | 摘要/删除/保留分界，工具返回落盘+引用 |
| 重启即失忆 | **长期记忆** | C14 | RAG 全链路：切分→Embedding→检索→重排→维护 |
| 进度无依归 | **外部状态** | C15 | 状态机外置、checkpoint 续跑、按需加载、子 Agent 隔离 |

一句话把三类分开：

- **短期记忆** = 还在上下文里的，怎么管、怎么压（本质是上下文工程）。
- **长期记忆** = 不在上下文里的，怎么存、怎么找（本质是检索）。
- **外部状态** = 压根不该放上下文的，放哪（本质是状态管理）。

## 二、出口标准对照

1. **会话压缩可用**——C13：跑 30 步以上任务，压缩后仍正确完成，成本可量化（见 C13-4 的及格线）。
2. **长期记忆检索跑通**——C14：有评测集，能量出召回率和「检索错导致答错」的比例。
3. **一个可断点续跑的任务**——C15：进程 kill 再起，从上次状态继续（幂等 + 中间产物落盘）。
4. **一次子 Agent 隔离实践**——C15-4：验证脏上下文隔离后主链路变干净。

## 三、综合自测

1. 一个 50 步的 Agent，每步查一次库返回 5000 行。它的成本会怎么涨？你至少能用哪两种手法压下去？
2. 「短期记忆」「长期记忆」「外部状态」的本质区别是什么？各举一个「放错了地方」的例子。
3. 你的知识库 10 万篇文档，用户问「型号 AB-123 的规格」。为什么纯向量检索可能漏，混合检索能救？
4. 断点续跑时，你发现某个「发邮件」步骤可能被执行两次。问题出在哪？怎么保证安全？
5. 什么情况下你会把一个子任务丢给子 Agent 隔离执行，而不是在主链路里直接跑？

## 四、参考答案要点

1. 成本随步数平方增长（每步都要为历史重复付费）。两手法：工具返回「落盘+引用」（C13-3）、会话压缩（C13-2）。
2. 短期=还在上下文里怎么管（上下文工程）；长期=不在上下文里怎么存怎么找（检索）；外部状态=不该放上下文的进度/产物（状态管理）。例：把任务进度放消息里（进程挂就丢）、把 3 页文档搭整套 RAG（过度设计）、把中间产物塞满上下文（预算黑洞）。
3. 向量检索不懂「精确字符串匹配」，可能漏掉含「AB-123」的段。混合检索加关键词（BM25）补精确匹配，合并去重。
4. 非幂等操作重复执行的风险。做法：执行前/后立刻打「已执行」标记，恢复时先查标记；或让操作本身幂等。
5. 子任务上下文很脏、且主任务只需要结论时（如「查竞品价格策略给我一句话结论」），用子 Agent 隔离，保主链路干净。
