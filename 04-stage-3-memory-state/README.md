# 阶段 3 · 记忆与状态
**层级**：阶段（阶段 3 共 3 门课）
**规模**：3 门课 / 15 篇正文（另含 3 篇课程索引）
**时长**：约 3.5–4.5 小时（含动手时间）
**前置**：阶段 1（上下文裁剪基础）、阶段 2（Agent 循环）
**产出**：会话记忆压缩跑通 + 长期记忆检索跑通 + 一个可断点续跑的任务

## 这个阶段解决什么问题

Agent 一旦跑长任务，会撞上两堵墙：

1. **上下文会爆**——几十步下来，消息数组塞满了工具返回，再继续要么超窗口，要么贵得离谱。
2. **重启即失忆**——进程一挂，任务进度、已经试过什么、用户说过什么偏好，全部归零。

这两件事对应三类完全不同的机制，混在一起谈是很多混乱的来源：

- **短期记忆**：还在上下文里的内容怎么管、怎么压缩（本质是上下文工程）
- **长期记忆**：不在上下文里的内容怎么存、怎么找回来（本质是检索）
- **外部状态**：压根不该放上下文的东西（任务进度、中间产物）该放哪

阶段 2 手写了一个最小 Agent，但它「无状态、记不住、扛不了长任务」。这一阶段给它装上三样东西：**会压缩的短期记忆、能检索的长期记忆、可恢复的外部状态**。

## 学完你能做到

1. 设计会话压缩策略：什么该摘要、什么该删、什么必须原样保留。
2. 搭通一条完整的 RAG 链路：切分 → Embedding → 存 → 检索 → 重排，并知道每个环节的坑。
3. 把任务进度外置，做到进程挂了能从断点续跑。
4. 用「按需加载」代替「全塞进去」，用子 Agent 隔离脏上下文。

## 推荐阅读顺序

1. **C13**— 先解决「上下文会爆」这堵最急的墙，它直接复用了阶段 1 的 C7。
2. **C14**— 长期记忆的检索链路，但**开篇先读「什么时候不需要 RAG」**——多数人上来就堆向量库，其实该先问该不该。
3. **C15**— 状态外置与断点续跑，是长任务的最后一块拼图；3.4 的子 Agent 隔离也是阶段 4「拆分」的先导。

## 阶段出口标准

做完这四件事再进阶段 4：

1. **会话压缩可用**：一个跑 30 步以上的任务，压缩后仍能正确完成，且成本可量化（压掉多少 token、成功率掉多少）。
2. **长期记忆检索跑通**：有评测集，能说出召回率和「检索错导致答错」的比例。
3. **一个可断点续跑的任务**：进程 kill 掉再起，能从上次状态继续。
4. **一次子 Agent 隔离实践**：验证脏上下文隔离后主链路是否变干净。
