# C16-3 · 编排模式一：路由与流水线
> 阅读约 12 分钟。目标：掌握两种「串行」编排拓扑——路由（按类型分发）和流水线（按阶段接力）。

## 1. 四种编排模式的全景

多 Agent 系统本质是一张「谁调用谁」的图。四种基本拓扑：

| 模式 | 拓扑 | 一句话 |
|---|---|---|
| **路由** | 一个入口 → 按类型分发到 N 个专家之一 | 把「对的事」派给「对的 Agent」 |
| **流水线** | A → B → C 顺序接力 | 把任务按阶段拆成一条链 |
| **主从** | 一个主 Agent 拆任务 → N 个从 Agent 并行干 → 回收 | 一个拆，多个干 |
| **黑板** | 多个 Agent 共享一块「黑板」读写协作 | 大家围绕共享状态协作 |

多数真实系统是这几种的**组合**，不是纯某一种。先分别吃透，再谈组合。

## 2. 路由（Router）

**拓扑**：一个入口 Agent（或纯规则），判断任务属于哪类，转给对应的专家 Agent。

```
          ┌→ 客服 Agent
用户输入 → 路由 ┼→ 技术 Agent
          └→ 售后 Agent
```

**适用**：任务类型**清晰可枚举、互不重叠**（客服/技术/售后、前端/后端问题）。

**关键**：路由判断本身要便宜——它不该是个「大模型推理半天」的重步骤，最好用轻量模型或规则做，否则入口就成瓶颈。

**失败传播**：路由判错类，任务就从起点错了。所以路由的准确率是这类系统的命门。

## 3. 流水线（Pipeline）

**拓扑**：任务按阶段串成一条链，每个 Agent 负责一个阶段，前一阶段的输出是后一阶段的输入。

```
需求 → [分析 Agent] → [设计 Agent] → [实现 Agent] → [审校 Agent] → 产出
```

**适用**：任务有**天然的顺序阶段**，且每个阶段产出可验证的中间物（分析报告 → 设计方案 → 代码 → 审校意见）。

**关键**：

- **阶段边界要清晰**：每个阶段「输入什么、产出什么」要定义清楚，否则阶段之间互相甩锅。
- **中间物要落盘**（呼应 C15-2）：阶段之间的交接物存下来，某阶段失败不必从头跑。

**失败传播**：流水线的失败是**级联**的——A 错了，B、C 全错。所以越靠前的阶段越要稳，前段错误会沿链放大。

## 4. 两者怎么选

| 你的任务 | 选 |
|---|---|
| 任务可分成互斥的类型 | 路由 |
| 任务有天然的顺序阶段 | 流水线 |
| 两者都有 | 组合：先路由分类型，每类内部走流水线 |

## 5. 小结

- 路由：按类型分发，命门是「路由判断要便宜且准」。
- 流水线：按阶段接力，命门是「阶段边界清晰、中间物落盘」，失败会级联。
- 多数真实系统是组合：先路由、再流水线。
