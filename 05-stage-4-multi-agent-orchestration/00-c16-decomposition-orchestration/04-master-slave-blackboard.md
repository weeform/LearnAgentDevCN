# C16-4 · 编排模式二：主从与黑板
> 阅读约 18 分钟。目标：掌握两种「并行/协作」拓扑——主从（一拆多干）和黑板（共享状态协作），并知道部分失败与不收敛怎么处理。

## 1. 主从（Master–Worker）

**拓扑**：一个主 Agent 负责拆任务、分派、回收结果，N 个从 Agent 并行干活，各干各的互不干扰。

```
                 ┌→ 从 Agent A（查中国市场）
主 Agent 拆任务 → ├→ 从 Agent B（查美国市场）   → 回收 → 主 Agent 汇总
                 └→ 从 Agent C（查欧洲市场）
```

**适用**：任务可以切成**互不依赖、可并行**的多个子任务（这就是 C16-1 的信号二）。

**关键**：

- **拆得干净**：子任务之间不能有共享状态或依赖，否则并行变串行。
- **回收要聚合**：N 个结果回来，怎么合并是 C18 的主题（投票/打分/去重）。
- **主 Agent 的职责要薄**：它只负责「拆、派、收」，别让它也下场干活——职责单一才可控。

**失败传播**：单个从 Agent 失败，主 Agent 可以**重试或降级**（换一个从 Agent 或跳过），整体更鲁棒；但主 Agent 本身失败，全盘皆停（单点故障）。

### 主从的骨架：并发 + 部分失败

主从的代码骨架其实很短，难点全在「有一个从 Agent 挂了怎么办」：

```python
async def run_master(task: str, subtasks: list[str]):
    results = await asyncio.gather(
        *(run_worker(task, st) for st in subtasks),
        return_exceptions=True,          # 关键：一个失败别炸掉全部
    )
    ok = [(st, r) for st, r in zip(subtasks, results) if not isinstance(r, Exception)]
    bad = [(st, r) for st, r in zip(subtasks, results) if isinstance(r, Exception)]
    return ok, bad
```

拿到 `bad` 之后，有三条路，**按「缺了这块结论还成不成立」来选**：

| 策略 | 什么时候用 | 代价 |
|---|---|---|
| **重试** | 错误是瞬时的（超时、限流、5xx） | 退避重试即可（C5-2），无副作用 |
| **跳过并标注** | 缺这块只是「不完整」，不是「错」 | 必须在最终结论里显式写出「欧洲市场缺失」 |
| **整体失败** | 缺一块结论就不成立（三方对账少一方） | 前面白跑，但比给出错结论好 |

最常见的错误是**第三种情况按第二种处理**：拿两个市场的数就敢下「全球趋势」的结论。缺数据不是罪，**假装数据齐了才是**。

> 判据：这个子任务的缺失，会让结论从「不完整」变成「错误」吗？会，就必须整体失败。

**主 Agent 只做三件事**：拆、派、收。它一旦下场干活（比如自己去补查欧洲市场），就同时承担了「编排」和「执行」两个职责——出问题时你分不清是拆错了还是干错了，这是主从系统最常见的失控点。

## 2. 黑板（Blackboard）

**拓扑**：多个 Agent 围绕一块**共享的「黑板」**读写协作——每个 Agent 把自己的发现写到黑板上，也从黑板读别人的发现，逐步逼近结论。

```
黑板（共享状态：假设、证据、部分结论）
  ▲ 写        ▲ 写
  │           │
Agent A     Agent B    （各自读黑板上的线索，补充自己的发现）
```

**适用**：任务需要**多方信息交叉、逐步收敛**的场景（例如多方协作做一份分析，各 Agent 各贡献一块拼图）。

**关键**：

- **黑板即状态**：黑板上的内容是共享真相源，这其实就是 C15-1「状态外置」在多 Agent 下的自然延伸。
- **要有收敛规则**：谁负责读黑板、什么时候算「讨论结束」，必须显式定义，否则黑板变成无限讨论。

**失败传播**：黑板是「污染会扩散」的——一个 Agent 往黑板上写了错误结论，其他 Agent 读了会跟着错。所以黑板上的内容最好**标注来源与可信度**（呼应 C14-4 的记忆污染）。

### 黑板的收敛规则：不定义就永远停不下来

黑板模式最容易失控的不是污染，是**不收敛**：每个 Agent 都能往板上加内容，加完又觉得别人的写法不对，一轮轮改，永远「还可以再完善一点」。

所以黑板必须有三样东西。

**一、条目结构固定**，四个字段缺一不可：

```json
{
  "claim": "欧洲市场需求同比下滑 8%",
  "source": "agent_b / 工具:market_data",
  "confidence": 0.7,
  "status": "open"          // open | confirmed | refuted
}
```

没有 `source` 就无法追溯谁说的、依据什么；没有 `status` 就永远吵不完——**争议必须能被「标记为已裁决」**。

**二、收敛条件显式写死**，至少满足其一就停：

```python
def should_stop(board, round_no, max_rounds=5):
    if round_no >= max_rounds:                 return True   # 硬上限，兜底
    if board.no_new_evidence_last_round:       return True   # 没新证据就别再吵
    if board.top_hypothesis.confidence >= 0.9: return True   # 够了就收
    return False
```

**三、必须有人负责裁决**。两个 Agent 给出矛盾结论时，黑板上不能同时挂着两条 `open`——要么由裁决者（一个专门角色，或人）定夺，要么按可信度规则降权。**放任矛盾并存，等于把问题推给了最终读结论的人。**

> 一句话：黑板的价值在「共享状态」，风险也在「共享状态」；决定它好不好用的，是收敛规则写没写死。

## 3. 四种模式一览

| 模式 | 拓扑 | 并行？ | 关键风险 |
|---|---|---|---|
| 路由 | 一入口 → N 专家之一 | 否（只走一个） | 路由判错 |
| 流水线 | A→B→C 接力 | 否 | 错误级联 |
| 主从 | 主拆 → N 从并行 | 是 | 主单点故障、聚合难 |
| 黑板 | 多 Agent 共享状态 | 可并行 | 错误扩散、不收敛 |

## 4. 组合才是常态

真实系统几乎都是组合。一个典型例子：

> **路由**（先判断任务类型）→ **主从**（主 Agent 拆成并行子任务）→ 每个子任务内部走**流水线**（阶段接力）→ 结果写回**黑板**（共享状态供汇总）。

别追求「纯某一种模式」，按任务形状拼。

## 5. 小结

- 主从：一拆多干，适合可并行子任务；主 Agent 职责要薄，聚合是难点。
- 黑板：多 Agent 共享状态协作，适合多方交叉收敛；要防错误扩散、定义收敛规则。
- 四种模式是积木，真实系统是组合。
