# C16-5 · 速查表与自测
> 阅读约 10 分钟。目标：把拆分判断与四种拓扑固化成一页，并用自测检验。

## 速查表

### 拆分判断

| 信号 | 特征 |
|---|---|
| 上下文污染 | 任务越跑越顾此失彼 |
| 需要并行 | 有互不依赖的独立子任务 |
| 职责互斥 | 敏感操作需最小权限隔离 |

拆前四问：① 单 Agent 真搞不定吗 ② 命中哪条信号 ③ 边界能否一句话说清 ④ 收益是否大于成本。

### 四项成本

token（3–10 倍，每 Agent 独立上下文）· 延迟（通信+串行）· 调试（失败点翻倍）· 一致性（新增 bug 类）。

### 四种编排模式

| 模式 | 拓扑 | 并行 | 关键风险 |
|---|---|---|---|
| 路由 | 一入口 → N 专家之一 | 否 | 路由判错 |
| 流水线 | A→B→C 接力 | 否 | 错误级联 |
| 主从 | 主拆 → N 从并行 | 是 | 主单点、聚合难 |
| 黑板 | 多 Agent 共享状态 | 可并行 | 错误扩散、不收敛 |

## 自测题

1. 一个任务要「同时查三个市场的行情，再汇总」。它命中哪条拆分信号？该用哪种拓扑？
2. 为什么「纯串行的拆分只会更慢」？token 为什么涨 3–10 倍？
3. 流水线模式里，A 阶段错了，B、C 会怎样？怎么降低这个风险？
4. 路由模式的命门是什么？为什么路由判断要「便宜」？
5. 黑板模式里，一个 Agent 写错了结论，为什么比单 Agent 出错更危险？

## 参考答案要点

1. 命中「需要并行」（三个市场互不依赖）。用「主从」拓扑：主 Agent 拆成三个并行子任务，回收后汇总。
2. 多 Agent 的延迟来自通信与串行等待，纯串行没有并行收益还叠加等待；token 涨因为每个 Agent 是独立上下文，system prompt、任务描述、历史各自重复付费。
3. 错误沿链级联，A 错 B、C 全错。降低风险：阶段边界清晰、中间物落盘（某段失败不必从头）、前段越稳越好。
4. 命门是「路由判错，任务从起点就错」。路由要便宜，因为它是每个任务必经的入口，若用重型推理会成瓶颈。
5. 黑板是共享真相源，错误结论会被其他 Agent 读到并跟着错，污染扩散。缓解：标注来源与可信度、定义收敛规则。
