# C16-5 · 速查表与自测
> 阅读约 14 分钟。目标：把拆分判断、四项成本、四种拓扑与交付物固化成一页，并用自测检验。

## 速查表

### 拆分判断

| 信号 | 特征 |
|---|---|
| 上下文污染 | 任务越跑越顾此失彼 |
| 需要并行 | 有互不依赖的独立子任务 |
| 职责互斥 | 敏感操作需最小权限隔离 |

拆前四问：① 单 Agent 真搞不定吗 ② 命中哪条信号 ③ 边界能否一句话说清 ④ 收益是否大于成本。

### 四项成本

token（3–10 倍，每 Agent 独立上下文）· 延迟（通信+串行）· 调试（失败点翻倍）· 一致性（新增 bug 类）。

### 四种编排模式

| 模式 | 拓扑 | 并行 | 关键风险 |
|---|---|---|---|
| 路由 | 一入口 → N 专家之一 | 否 | 路由判错 |
| 流水线 | A→B→C 接力 | 否 | 错误级联 |
| 主从 | 主拆 → N 从并行 | 是 | 主单点、聚合难 |
| 黑板 | 多 Agent 共享状态 | 可并行 | 错误扩散、不收敛 |

### 从信号到拓扑：一条决策路径

先问「单 Agent 能不能跑通」，再问「命中哪条信号」，最后才落到拓扑：

| 你的处境 | 先用什么 | 为什么 |
|---|---|---|
| 一个 Agent 越跑越糊 | 子 Agent 隔离（C15-4） | 换的是上下文，不是架构，成本最低 |
| 子任务互不依赖 | 主从 | 唯一能在墙钟时间上真省钱的 |
| 有天然顺序阶段 | 流水线 | 阶段边界天然就是验收点 |
| 任务类型可枚举 | 路由 | 一次判断省掉全链开销 |
| 多方交叉、要逐步收敛 | 黑板 | 但必须先把收敛规则写死 |

顺序上有个通用套路：**能隔离就不拆，能串行就别并行，能规则就别问模型**。

### 三个最常见的误判

| 症状 | 容易误判成 | 实际往往是 |
|---|---|---|
| 结论质量随步数下滑 | 该拆多 Agent | 上下文污染，先裁剪/摘要（C7、C15） |
| 任务太慢 | 该上并行 | 先定位瓶颈调用；串行链拆分不会变快 |
| 各 Agent 结论打架 | 聚合算法不行 | 多半是交接包缺「依据 + 不确定性」（C18-1） |

### 本课交付物（对应阶段 4 出口标准）

读完不算完，这三样交得出来，C16 才算过：

1. **一个可拆、可并行的小任务**——至少 2 个 Agent，拓扑写明白（主从还是流水线）。
2. **一份对比数据**——同一任务单 Agent vs 多 Agent 的成功率、token、耗时。没有这组数，你的「拆分有收益」就只是感觉。
3. **一条负结果**——一次「拆了反而更差」的记录及原因。这条比前两条值钱：它证明你真的算过账，而不是照着教程抄。

## 自测题

1. 一个任务要「同时查三个市场的行情，再汇总」。它命中哪条拆分信号？该用哪种拓扑？
2. 为什么「纯串行的拆分只会更慢」？token 为什么涨 3–10 倍？
3. 流水线模式里，A 阶段错了，B、C 会怎样？怎么降低这个风险？
4. 路由模式的命门是什么？为什么路由判断要「便宜」？
5. 黑板模式里，一个 Agent 写错了结论，为什么比单 Agent 出错更危险？
6. 主从系统里，三个从 Agent 有一个超时了，你怎么决定该重试、跳过还是整体失败？
7. 黑板模式下，两个 Agent 对同一事实给出相反结论、都标着 `open`，该怎么办？

## 参考答案要点

1. 命中「需要并行」（三个市场互不依赖）。用「主从」拓扑：主 Agent 拆成三个并行子任务，回收后汇总。
2. 多 Agent 的延迟来自通信与串行等待，纯串行没有并行收益还叠加等待；token 涨因为每个 Agent 是独立上下文，system prompt、任务描述、历史各自重复付费。
3. 错误沿链级联，A 错 B、C 全错。降低风险：阶段边界清晰、中间物落盘（某段失败不必从头）、前段越稳越好。
4. 命门是「路由判错，任务从起点就错」。路由要便宜，因为它是每个任务必经的入口，若用重型推理会成瓶颈。
5. 黑板是共享真相源，错误结论会被其他 Agent 读到并跟着错，污染扩散。缓解：标注来源与可信度、定义收敛规则。
6. 看「缺失会不会让结论从『不完整』变成『错误』」：瞬时错误（超时/限流）先退避重试；只是不完整 → 跳过并在最终结论里显式标注缺失；缺一块结论就不成立（如三方对账）→ 整体失败。绝不能拿两份数据假装齐全。
7. 不能放任两条 `open` 并存。要么由裁决者（专门角色或人）定夺并置为 confirmed / refuted，要么按来源可信度规则降权；无论如何都要把「此处存在分歧」写进最终结论的不确定性里。
