# C17-2 · LangGraph / AutoGen / CrewAI 横评
> 阅读约 12 分钟。目标：用三个维度看清三个主流框架的定位与取舍。
>
> ⚠️ 时效提示：框架半年一变，下面的定位与版本细节以写作为准。重点是「用什么维度看」，不是背结论。

## 1. 先给结论

| 框架 | 定位 | 适合 | 代价 |
|---|---|---|---|
| **LangGraph** | 用「图」显式表达控制流与状态 | 复杂流程、长任务、要精细控制 | 上手陡、样板代码多 |
| **AutoGen** | 多 Agent「对话式」协作 | 研究型、探索型多 Agent 协作 | 控制流较隐式、结果较难精确控制 |
| **CrewAI** | 「角色 + 任务」的高层封装 | 快速搭一条角色流水线 | 低层控制受限、深度定制难 |

## 2. LangGraph：状态机式，最显式

LangGraph 把 Agent 流程建模成一张**图**：节点是「动作」，边是「转移」，状态是显式的、可持久化的对象。

- **状态管理**：强。显式状态 + 内置 checkpoint，天然支持断点续跑、时间旅行回放。
- **可观测性**：强。配合 LangSmith 有完整 trace 与执行图可视化。
- **逃生舱**：好。节点里可以写任意代码，随时降级到原生 SDK 调用。
- **代价**：要学图的思维，样板代码多，小任务显得重。

一句话：**要精细控制复杂流程、跑长任务，LangGraph 是当前较稳的选择。**

## 3. AutoGen：对话式，协作最自然

AutoGen 的核心抽象是「多个 Agent 互相发消息、对话协作」，适合让几个 Agent「讨论着把事办了」。

- **状态管理**：偏隐式，状态多在对话历史里，显式持久化不如 LangGraph。
- **可观测性**：中等，有日志和会话记录，但控制流的显式程度不如图。
- **逃生舱**：中等，Agent 内部能写代码，但协作框架本身较「包」。
- **代价**：结果受「对话走向」影响，精确控制输出较难。

一句话：**适合「探索/研究/头脑风暴」这类需要 Agent 自主对话的场景，不适合需要精确控制每一步的生产流程。**

## 4. CrewAI：角色式，最快上手

CrewAI 用「角色（Role）+ 任务（Task）+ 团队（Crew）」的高层抽象，几行代码就能搭一条「研究员 → 写手 → 审校」的流水线。

- **状态管理**：偏隐式，封装层高，低层状态较难直接操控。
- **可观测性**：中等，有任务级记录，但细粒度 trace 不如图式框架。
- **逃生舱**：较弱，高层封装多，想绕到原生调用更费劲。
- **代价**：快，但深度定制和复杂控制流受限。

一句话：**适合「快速把一条角色流水线跑起来」，不适合复杂分支、精细控制。**

## 5. 用三问快速定位自己

| 你的需求 | 倾向 |
|---|---|
| 复杂控制流、长任务、要断点续跑 | LangGraph |
| 多 Agent 自主对话、探索型任务 | AutoGen |
| 快速搭角色流水线、验证想法 | CrewAI |
| 控制流简单、想完全掌控 | 自研（见 C17-3） |

## 6. 小结

- LangGraph = 图/状态机，最显式、最可控、上手陡。
- AutoGen = 对话式协作，自然但结果难精确控制。
- CrewAI = 角色式高层封装，最快上手、深度定制受限。
- 用「状态管理 / 可观测性 / 逃生舱」三问定位，别背结论。
