# C18-1 · 结构化消息 vs 自然语言
> 阅读约 15 分钟。目标：Agent 之间传消息，选结构化还是自然语言——这个选择决定了后面聚合有多难；跨出系统边界时，还要知道该换哪套协议。

## 1. 两种消息格式

| 格式 | 例子 | 特点 |
|---|---|---|
| **结构化** | JSON 字段：`{"结论": "涨", "置信度": 0.8, "依据": "..."}` | 字段明确、可校验、可聚合 |
| **自然语言** | 一段话：「我觉得市场会涨，因为……」 | 灵活、表达丰富、难程序化处理 |

## 2. 各自的强项与代价

**结构化消息**：

- ✅ 可程序化校验（字段对不对、类型对不对）。
- ✅ 可聚合（多个 Agent 的「置信度」字段直接比大小）。
- ✅ 不丢信息（字段都在）。
- ❌ 要预先定义 schema，灵活度低；表达不了太复杂的意思。

**自然语言消息**：

- ✅ 灵活，能表达复杂、模糊、需要发挥的内容。
- ❌ 难校验（「我觉得还行」到底行不行？）。
- ❌ 难聚合（三段话没法直接「取平均」）。
- ❌ 容易被误读。

## 3. 怎么选：看「谁来消费这条消息」

> **给程序/下游 Agent 处理的，用结构化；给模型「理解、发挥、综合」的，用自然语言。**

- Agent 之间**传递数据、结论、状态** → 结构化（像 API 的返回）。
- 需要模型**综合、润色、判断**的中间内容 → 自然语言。

一个常见错误：**让 Agent 之间互相写大段自然语言**，结果每个下游 Agent 都要「重新读懂」上游的一大段话，既贵又容易误读。

## 4. 一个好用的折中：结构化 + 自然语言摘要

很多场景最优是「两者结合」：

```json
{
  "conclusion": "看涨",          // 结构化：机器可直接处理、可聚合
  "confidence": 0.78,            // 结构化：可比较
  "evidence": ["财报超预期", "资金流入"],   // 结构化：可追溯
  "summary": "财报超预期且北向资金持续流入，短期看涨。"  // 自然语言：供模型综合
}
```

**结论、置信度、依据用结构化字段**（可校验、可聚合），**再附一段自然语言摘要**（供需要综合时用）。

## 5. 跨系统通信：A2A 协议

前四节讲的是「同一个系统内的几个 Agent 怎么说话」。一旦对方是**别的团队、别的厂商、别的框架**部署的 Agent，缺的就不是格式约定了，而是一套**协议**。

这就是 A2A（Agent2Agent）：2025 年由 Google 发起，同年捐给 Linux 基金会，和 MCP 形成明确分工——

| 协议 | 连接的是 | 调用的性质 |
|---|---|---|
| **MCP**（见 C12） | Agent ↔ 工具 / 数据源 | 短、无状态、Agent 主动调 |
| **A2A** | Agent ↔ Agent | 长、有状态、可中途反问 |

**为什么 MCP 顶不了这个位置**：MCP 把「工具」抽象成一次函数调用；而 Agent 之间要委派的是「一个可能跑十分钟、中途还得回来问你的任务」。前者是 RPC，后者是**有生命周期的委派**，语义不同。硬套只能把状态塞进参数里，最后不可维护。

A2A 的四个核心概念，各解决一个痛点：

1. **Agent Card** —— 能力名片（默认在 `/.well-known/agent-card.json`），声明我会什么、端点在哪个、怎么鉴权。解决「**怎么发现**对方能干什么」。
2. **Task** —— 有状态的长任务对象，带生命周期（submitted → working → input-required → completed / failed / canceled）。解决「**长任务不能靠一次请求-响应**」——这就是 C15 的外部状态机，只是换成了协议标准。
3. **Message / Part** —— 消息由若干 Part 组成：文本、文件、结构化数据。**DataPart 就是 JSON**，正好接上 C18-1 的结论：能结构化就别传自然语言。
4. **流式与回调** —— SSE 推过程、push notification 通知完成。解决「**跑十分钟的任务，用户怎么知道进展**」。

**什么时候用**：跨组织 / 跨厂商 / 跨框架，对方是独立部署的服务。
**什么时候别用**：自己系统内那几个 Agent——进程内函数调用或消息队列更简单，套协议只多出序列化与调试成本。

三个坑：

- **Agent Card 是信任问题，不是发现机制**。它本质是对方自称的能力声明，谁能发现你、你能信谁，要靠白名单加鉴权（OAuth / OIDC），不能默认可信（呼应 C12-4 的仿冒 server 风险）。
- **Task 必须幂等**。网络重试、回调重复投递是常态，同一个 task id 重放不能重复执行副作用（C5-2 的幂等键）。
- **`input-required` 就是人工介入点**。这个状态天然对应 C23-3 的 HITL——任务卡在等人回答时，产品要有地方把人拉进来。

> 时效提示：A2A 仍在演进，字段与传输细节以官方规范为准。这篇要带走的是**分工判断**：工具走 MCP，Agent 之间走 A2A，自家内部的协作不必上协议。

## 6. 小结

- 结构化消息：可校验、可聚合、不丢信息，但要预定义 schema。
- 自然语言：灵活但难校验、难聚合、易误读。
- 原则：给程序/下游处理的用结构化，给模型综合的用自然语言；常用「结构化字段 + 自然语言摘要」折中。
- 跨系统才需要 A2A：MCP 管 Agent↔工具（短、无状态），A2A 管 Agent↔Agent（长、有状态、可反问）；自家内部协作不必上协议。
