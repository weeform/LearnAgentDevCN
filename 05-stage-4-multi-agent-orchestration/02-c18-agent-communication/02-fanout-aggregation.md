# C18-2 · 扇出与聚合
> 阅读约 18 分钟。目标：N 个 Agent 的结果回来了，用投票、打分、去重合并把它们变成一个可信结论；并知道 N 取几、什么错误投票救不了。

## 1. 扇出之后，聚合是难点

「主从」模式里，主 Agent 把任务扇出给 N 个从 Agent，现在 N 份结果回来了。**聚合不是「拼在一起」，而是「消除分歧、去重、形成唯一结论」**——这正是 C16-2 说的「一致性成本」。

三种基本聚合方式：

## 2. 投票（多数决）

N 个 Agent 各给一个结论，取**多数**。

- 适用：结论是**离散选项**（涨/跌、A/B/C、通过/驳回）。
- 代价：简单，但「多数」不等于「对」——3 个 Agent 可能因为同样的错误数据一起错。
- 缓解：投票时要求各自给出**依据**，而不是只给结论，便于事后查「为什么多数是错的」。

## 3. 打分（加权）

N 个 Agent 各给一个**分数/置信度**，加权合并。

- 适用：结论是**连续值或带置信度**的（评分、概率、质量分）。
- 关键：**权重怎么定**？可以用历史表现（谁过去更准）、来源可靠性（谁的数据更权威）。
- 陷阱：别用「Agent 自报的置信度」当权重——模型对自己「多确定」的判断常常不准。用**外部信号**（历史准确率）加权更可靠。

## 4. 去重合并

N 个 Agent 的结果有重叠，把相同的合并、去重、去冲突。

- 适用：结论是**集合/列表**（N 份候选方案、N 条证据）。
- 做法：合并后按「内容相似度」去重（呼应 C14-4 的记忆去重），冲突项显式标出。
- 关键：去重要保守——宁可多留一条「疑似重复」，也别误删一条不同的。

### 三种聚合的代码骨架

```python
from collections import Counter

def vote(answers: list[dict]) -> dict:
    c = Counter(a["conclusion"] for a in answers)
    top, n = c.most_common(1)[0]
    if n * 3 < len(answers) * 2:              # 不到 2/3，不算共识
        return {"status": "disputed", "answers": answers}
    return {"status": "ok", "conclusion": top,
            "evidence": [a["evidence"] for a in answers
                         if a["conclusion"] == top]}

def weighted(scores: list[dict], weights: dict) -> float:
    tot = sum(weights[s["agent"]] for s in scores)
    return sum(s["score"] * weights[s["agent"]] for s in scores) / tot
```

两个细节最容易写错：

- **投票要有共识门槛**。2:1 就宣布「多数决通过」，等于把 33% 的反对意见悄悄吃掉了。设 2/3 门槛，不到就转成「分歧」处理（见下节）。
- **权重表离线维护**。写死一张 `{agent: 历史命中率}`，定期用评测集更新；绝不要在运行时让模型自报「我有多确定」——那是它最不靠谱的输出之一。

### N 该取几

- **N=1** 谈不上聚合；**N=2** 一旦分歧就是平票，无法裁决。
- **N=3 是最小可行数**——能形成 2:1，也能识别「三方全不同」这种异常。
- **N 越大成本线性涨、收益递减**。多数场景 3–5 就够，再多，边际收益基本被成本和延迟吃掉。

### 最危险的失败：同源错误

三个 Agent 都从同一张过期表里读数，投票结果 3:0「一致通过」。**一致性极高，结论全错。**

> 投票能消除的是「各自独立的随机错误」，消不掉「共同的系统性偏差」。

所以提高 N 不如**换数据源**：让几个 Agent 走不同的工具、不同的源、甚至不同的检索方式。让同一个 Agent 跑三遍，只是把同一个偏见重复三次——票数变多了，信息量没变。

## 5. 聚合失败怎么办

N 个结果互相矛盾、聚不出唯一结论时，别硬选一个：

1. **回传分歧**：把「N 个不同结论 + 各自依据」原样交给一个「裁决 Agent」或人，做最终判断。
2. **降级重试**：让分歧最大的几个 Agent 带着「对方的不同意见」再跑一轮。
3. **如实报告**：给用户「结论不一致 + 各方依据」，而不是假装有一个确定答案。

> 聚合的第一原则：**宁可不给唯一答案，也别给一个「看起来确定、其实是硬凑」的答案。**

## 6. 小结

- 聚合三方式：投票（离散结论，多数决）、打分（连续值，外部信号加权）、去重合并（集合结论，保守去重）。
- 别用模型自报置信度当权重，用历史表现/来源可靠性。
- 投票要设 2/3 共识门槛；N 取 3–5，再多是被成本吃掉的边际收益。
- 提 N 不如换数据源：投票消不掉同源偏差，三个 Agent 读同一张错表只会 3:0 一致地错。
- 聚不出唯一结论就如实回传分歧，别硬凑。
