# C18-4 · 阶段 4 总复习与自测
> 阅读约 12 分钟。目标：把阶段 4 串成一条链，对照出口标准做综合自测。

## 一、阶段 4 串讲

从「该不该拆」到「怎么让它们协作」，一条完整链：

| 环节 | 课程 | 核心结论 |
|---|---|---|
| 先判断该不该拆 | C16 | 默认不拆；命中「污染/并行/职责互斥」信号才拆 |
| 算清代价 | C16 | token 3–10 倍、延迟、调试、一致性四项成本 |
| 选编排拓扑 | C16 | 路由/流水线/主从/黑板，多为组合 |
| 选框架还是自研 | C17 | 比三维度（状态/可观测/逃生舱），简单就自研 |
| 通信与聚合 | C18 | 结构化消息、科学聚合、防传话游戏 |

一句话串起来：

> **先判断该不该拆 → 拆了算清代价 → 选拓扑 → 选落地方式 → 设计通信与聚合。**

## 二、出口标准对照

1. **一个可拆任务、可并行的小型系统**——C16：至少 2 个 Agent，有明确拓扑（如主从）。
2. **一份对比数据**——同一个任务，单 Agent vs 多 Agent 的成功率、token、耗时（C16-2 的成本 + 实测）。
3. **一次负结果记录**——至少记录一个「拆了反而更差」的尝试及原因（呼应 C16-1 的「多数情况不该拆」）。

## 三、综合自测

1. 一个任务「先查数据、再写报告、再审核」，三步有先后。它该拆吗？如果拆，用哪种拓扑？为什么不用主从？
2. 你拆了一个「主从」系统，3 个从 Agent 各给一个结论，互相矛盾。你会怎么聚合？如果聚不出唯一结论怎么办？
3. 为什么说「多 Agent 只有可并行时才能在墙钟时间上赢」？纯串行拆分为什么更慢？
4. 你发现 A→B→C 的流水线里，最终结论经常和 A 的原始发现对不上。最可能是哪个问题？怎么防？
5. 一个框架「上手快但包得很死」，另一个「上手慢但能随时降到原生调用」。按阶段 4 的判断标准，你更倾向哪个？为什么？

## 四、参考答案要点

1. 有先后顺序，是「流水线」拓扑（查数据→写报告→审核接力）。不该用主从，因为三步有依赖、不能并行，主从适合互不依赖的可并行子任务。
2. 按结论类型选：离散用投票（多数决），但别只给结论、要附依据；聚不出唯一结论就回传分歧（把各方结论+依据交给裁决 Agent 或人），别硬凑。
3. 多 Agent 的延迟来自通信和串行等待；只有互不依赖的部分才能并行省时间。纯串行拆分没有并行收益，还叠加了通信开销，只会更慢。
4. 最可能是「传话游戏」——信息在层层传递中被摘要/误读/选择性转述损耗。防法：传结构化数据、传原始引用不传摘要、减少层级、标注确定性。
5. 更倾向「能降到原生调用」的那个——因为逃生舱好，框架不锁死我；「上手快」的便利若以「被锁死」为代价，真实收益反而低（框架收益 = 省的时间 − 锁死的代价）。
