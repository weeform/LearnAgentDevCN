# C20-1 · 评测集怎么造
> 阅读约 12 分钟。目标：造出一把「能判断改动好坏」的尺子——评测集，并知道多少条够用、从哪来、怎么覆盖真实分布。

## 1. 一句话结论

> 没有评测集，你改 prompt、换模型、调参数，全是在「凭感觉赌一把」。

Agent 不是确定性程序（见 C19-1），改一处效果可能变好也可能变坏，而且你说不清为什么。评测集就是那把**尺子**：每次改动后跑一遍，数字涨了就是好，跌了就是坏。

## 2. 多少条够用

本课程口径：

| 场景 | 条数 | 说明 |
|---|---|---|
| 起步 / 个人项目 | 30 条 | 能看出「明显变好/变坏」，阶段 6 项目的验收线 |
| 真实上线 | 100+ | 能按子任务拆分类别，各自跑分 |
| 追求统计显著 | 300+ | 才谈得上「差异显著」 |

> 经验值：30 条是「有没有烂到不能看」的量级，不是「能不能上线」的量级。30 条全对也不代表生产没问题——它只是让你改 prompt 时不至于瞎。

为什么是 30 而不是 3？因为单条结果噪声极大（同一个 prompt 跑两次分都不同），30 条做平均才能把噪声压到可接受范围。3 条里 1 条翻车，你无法判断是「这次改坏了」还是「本来就随机」。

## 3. 从线上真实流量采样，不是手编

新手最容易犯的错：自己拍脑袋编 30 条「看起来合理」的问题。结果评测集和真实用户问的东西**根本对不上**，你在评测集上拿了 95 分，线上照样崩。

正确来源，按优先级：

1. **线上真实 trace 采样**（最佳）：把真实运行里用户的输入原样抽出来当用例。C19 的 trace 到这里派上用场——trace 记录里全是现成的评测样本。
2. **客服 / 工单 / 日志里的高频问题**：次优，但也是真实分布。
3. **手编兜底**：只用来补前两者覆盖不到的边界，永远只占少数。

> 反直觉：评测集的「真实」比「难」更重要。20 条真实高频问题，价值远大于 100 条你臆想的刁钻问题。

## 4. 黄金集与人工标注的成本

光有「问题」还不够，还要有「正确答案」才能打分。这个「问题 + 正确答案」的集合叫**黄金集（golden set）**。

正确答案从哪来？要么人写，要么从历史 trace 里挑「当时用户点了满意」的那次输出当参考答案。

> 人工标注是评测里最贵、最慢的一环。所以本课程的策略是「**30 条人肉精标起步，100 条靠 trace 回放 + 抽样精标**」，而不是一上来就标 500 条——你会在标注上烧掉一周，然后发现 prompt 已经改了三版。

一条黄金样本的最小结构：

```python
{
    "input": "帮我把北京明天天气查出来，并判断要不要带伞",
    "expected": "带伞（因为有小雨）",   # 正确答案，判断「对不对」的锚
    "source": "trace_2026-10-20",      # 从哪采的，便于追溯
    "tags": ["天气", "工具调用"],       # 分类，便于分维度看分
}
```

## 5. 覆盖真实分布：长尾与失败路径

评测集最容易犯的第二个错：**全是「阳光大道」用例**——正常、清晰、模型本来就会答的问题。这会导致评测分虚高，真实上线一塌糊涂。

要刻意覆盖三类：

| 类型 | 为什么要覆盖 | 例子 |
|---|---|---|
| 高频常规 | 决定大盘分数 | 「查天气」 |
| 长尾 / 罕见 | 少数但真实存在 | 「用方言问天气」 |
| 失败路径 | 最值钱，最容易被漏 | 「工具报错时能不能自己纠正」 |

> 失败路径是评测集里最值钱的部分。你优化 Agent 时最想知道的，就是「它遇到错误能不能救回来」（呼应 C19-3 里「失败的必留」）。但失败样本在线上占比低，靠随机采样采不到，得**专门从失败 trace 里捞**。

## 6. 评测集是「防回归」的资产

造评测集最容易被低估的价值：它不是你「今天」用的，是你「以后每次改动」都要用的。

> 你花了半天造的 30 条集，会在未来一年里被跑几百次——每次改 prompt、换模型、升框架，都靠它兜底。所以它是**资产，不是一次性开销**。

这意味着两条工程要求：

1. **版本化**：评测集存进代码库（或数据集仓库），随代码一起演进，别散在某人电脑里。
2. **只增不减**：发现线上新案例就补进去，老样本不轻易删（除非业务真的变了）。

## 7. 小结

- 评测集是尺子，没有它，改动好坏只能靠猜。
- 30 条起步看趋势，100+ 才够按子任务拆分，300+ 才谈显著。
- 从真实 trace 采样，不手编；人工只精标黄金集，控制在 30 条左右起步。
- 刻意覆盖长尾与失败路径，失败样本要专门捞。
- 评测集是长期资产：版本化、只增不减。
