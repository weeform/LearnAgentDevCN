# C20-3 · judge 自带哪些偏差
> 阅读约 14 分钟。目标：认清 LLM-as-judge 不是客观裁判，识别五种已知偏差，并掌握可落地的缓解与量化手段。

## 1. 一个必须接受的前提

> judge 是有偏的。你假装它客观，评测结果就是骗自己。

LLM-as-judge 也是 LLM，它的打分会被训练偏好、上下文顺序、文本风格悄悄影响。好消息是：这些偏差**已知、可量化、可缓解**。坏消息是：它们不会自己消失。

## 2. 偏差一：偏爱长答案

judge 倾向于给「更长、更详细」的回答打高分，哪怕长出来的部分是在说废话。

- 原因：训练数据里「详细」常和「高质量」强相关，judge 把这层相关性学成了偏好。
- 危害：逼着 Agent 变啰嗦，token 成本上升（呼应 C21），准确率却没涨。

**缓解**：rubric 里明确写「只按判据给分，长度不计分」；必要时给回答设长度上限，超长扣分。

## 3. 偏差二：偏爱「自己」的输出

同一个厂商的模型，倾向给「同厂商模型生成的回答」打更高的分。用 A 厂的模型当 judge，A 厂的候选答案容易占便宜。

- 危害：跨厂商换模型做对比时，结果被 judge 的「裙带关系」污染。

**缓解**：

1. **跨厂商配 judge**：候选是 A 厂，就用 B 厂模型当 judge，错开厂商。
2. **多 judge 投票**：用 2–3 个不同模型打分取平均，对冲单一偏好。

## 4. 偏差三：位置偏差

成对比较或列表里，judge 倾向于认为「先出现的 / 排在前面的」更好。候选 A 放前面，A 胜；调个个儿，B 胜——同一个 judge、同一对答案，结论相反。

> 这是最容易被忽略、也最好验证的一个偏差：你把同一对答案顺序对调再打一次分，如果结论翻转，位置偏差就实锤了。

**缓解**：

1. **随机化顺序**：每次打分随机 A/B 顺序。
2. **位置对调取平均**：A 放前、A 放后各打一次，两次结果取平均。成本翻倍，但这是成对比较的「标配」。

```python
# 位置对调取平均：一次 A/B，一次 B/A
def pairwise_avg(judge, a, b):
    s1 = judge(a, b)   # A 在前
    s2 = judge(b, a)   # B 在前
    return (s1 - s2 + 1) / 2   # 归一化到 0..1，1 表示 A 明确更好
```

## 5. 偏差四：对格式 / 文笔的隐性偏好

judge 会不自觉被「排版漂亮、用词正式、用了小标题 / 列表」的回答打动，而不是只看内容对不对。

- 危害：格式党胜出，内容正确但朴素直白的回答被误杀。

**缓解**：判据聚焦「事实对错、是否满足要求」，rubric 里显式声明「忽略排版与文风」。

## 6. 通用心法：用「对比」替代「绝对打分」

四种偏差的共同根源：**让 judge 凭空给一个绝对分，它只能靠口味**。化解之道是让它做**相对判断**——跟一个已知正确的锚对比。

| 做法 | 说明 |
|---|---|
| 锚定基准答案 | 把黄金答案（C20-1）和候选答案一起给 judge，让它判断「候选是否等价于/好于基准」 |
| 成对比较替代打分 | 不问「这答几分」，问「A 和 B 谁更好」 |

> 相对判断比绝对判断稳得多：让人说「这篇 83 分」很难，但让他说「这篇比那篇好」容易且可靠。judge 同理。

## 7. 偏差五：分数尺度会漂移

前四种是「同一次打分内部的偏好」，还有一种是跨批次的：**同一个 rubric，两批样本的分不可比**。judge 对「7 分」的理解会随这批样本的整体水平移动——这批整体都差时，勉强及格的那条也可能拿 8 分。

危害很具体：这周平均 7.2，下周 7.5，你以为变好了，其实只是这批样本更难、judge 悄悄放宽了尺度。**你测到的是 judge 的心情，不是系统的进步。**

缓解两条：

- 评测尽量只用**通过 / 不通过**或**分级枚举**（优/良/差），不用 1–10 连续分；
- 必须跨批次比较时，每批都掺入**同一组锚点样本**（固定的好、坏各 2 条），看锚点分数的漂移量再做校准。

## 8. 偏差必须被量化

最后一条硬规则：**不要「感觉」judge 准不准，要测出来**。

做法：拿一批你已经人工定过对错的样本（就是 C20-1 的黄金集），让 judge 打分，算 judge 和人工的**一致率（agreement）**。一致率低于阈值（经验值 90%），说明你的 rubric 或 judge prompt 有问题，先修 judge 再用它。

```python
def agreement(judge, human):
    return sum(j == h for j, h in zip(judge, human)) / len(human)
```

**raw agreement 的陷阱**：朴素一致率会被类别不平衡抬高。如果黄金集里 90% 的样本都是「通过」，judge 无脑全判通过就能拿到 90%——它其实什么都没判，却通过了你的阈值。

三条修正：

1. 黄金集正负样本大致均衡（至少 3:7），别一边倒；
2. 除 raw agreement 外再看 **Cohen's kappa**（扣掉「碰巧一致」的部分），kappa 低于 0.6 基本不可用；
3. 分开统计**误判方向**：把「好」判成「坏」（误杀）会阻碍优化，把「坏」判成「好」（漏放）会把问题放出去——后者更危险，要单独设更严的阈值。

> 一致率是 judge 的「体检报告」。没测过一致率的 judge，打出来的分一律存疑。

## 9. 小结

- 五种偏差：偏爱长答案、偏爱同厂商、位置偏差、格式文笔偏好、分数尺度漂移。
- 缓解：长度不计分、跨厂商 + 多 judge 投票、随机化顺序 + 对调取平均、判据聚焦内容、用锚点校准。
- 通用心法：用「与黄金答案对比」替代「绝对打分」，相对判断更稳。
- judge 偏差必须被量化——先测一致率（并看 kappa 与误判方向），再信任打分。
