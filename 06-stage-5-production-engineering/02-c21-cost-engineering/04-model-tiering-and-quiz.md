# C21-4 · 模型分级 + 速查自测
> 阅读约 13 分钟。目标：建立「贵模型做难活、便宜模型做简单活」的分级路由直觉，并用速查表与自测固化本课全部结论。

## 1. 模型分级：最猛的降本杠杆

C3-3 给过一个观察：同家族内价差可达 25 倍（如 GPT-5 nano vs GPT-5.5）。这意味着**与其抠 token，不如把「简单活」从贵模型搬到便宜模型**——省的是 20 倍，不是 20%。

分级的基本盘：

| 任务类型 | 例子 | 该派给谁 |
|---|---|---|
| 分类 / 意图识别 / 路由 | 判断用户想问什么、该走哪个工具 | 便宜模型 |
| 摘要 / 改写 / 提取 | 把工具返回压成要点、抽字段 | 便宜模型 |
| 推理 / 多步规划 / 生成 | 分析、决策、写最终答案 | 贵模型 |
| 兜底 / 评审 | 检查结果对不对、要不要重来 | 贵模型 |

> 一句话：**贵的做「想」，便宜的做「看」。**凡是「读一下、归个类、压缩一下」的活，交给便宜模型绰绰有余。

## 2. 分级阈值怎么定（不是拍脑袋）

把任务派给哪一档，看两个维度，缺一不可：

1. **任务难度**：便宜模型能不能稳定胜任？（用 C20 的评测集跑分验证，不是「感觉它能」）
2. **错误代价**：这类任务错了，代价多大？（分类错了也许只是多调一次；生成错了可能直接发错结论给用户）

```
分级决策矩阵：
  难度低 + 代价低 → 便宜模型（放心）
  难度低 + 代价高 → 便宜模型 + 贵模型评审兜底
  难度高 + 代价低 → 贵模型
  难度高 + 代价高 → 贵模型 + 人工确认（接 C23）
```

> 反直觉：**「便宜模型 + 贵模型评审」常常比「全程贵模型」更稳也更省**——贵模型只做终审，工作量小、成本可控，却补上了便宜模型最怕的「答错了没人发现」。

## 3. 分级的落地顺序

1. 先找出「占比最大的简单活」（通常是分类、摘要、路由）。
2. 用评测集确认便宜模型在这些活上的准确率达标（C20）。
3. 上线路由：简单活分流到便宜模型，难活留贵模型。
4. 监控两类指标：**成本下降幅度**（C21-1 的 `task_cost`）+ **质量有没有掉**（C20 的评测回归）。

> 分级不是一次性的。模型价格和能力一直在变，**每季度重新跑一次评测 + 算一次账**，看当前的分档还划不划算。这也是 C22（模型选型与路由）要展开的主题。

## 速查表

### 单位任务成本

- 最小核算单位是「任务」，不是「调用」。
- 边界：用户输入 → 最终答案，中间所有调用/工具/重试全计入。
- 公式复用 C3-3 四桶口径，工具返回回填 = 重新计费。
- 三个放大器：多轮、工具返回回填、重试；多 Agent 3–10 倍（C16-2）。

### 预算与告警

| 层 | 粒度 | 防什么 |
|---|---|---|
| 按任务 | 单次上限 | 单次失控 |
| 按用户 | 周期上限 | 刷量、公平 |
| 按天 | 全局上限 | 整体跑飞 |

逼近 80% 告警不打断；超限 100% 熔断。超额优先「降级/硬收口」，其次「停」。预算须与 C11 步数上限、C23 权限配合。

### 缓存命中率

- 按 token 算：`in_cached / 总输入`，别按次数算。
- 提升：稳定前缀放前、易变放后、历史只追加、同文档连续问（C2-5 / C7-4）。
- 暴跌 = 前缀被改坏的信号，设告警。

### 模型分级

- 贵模型做「想」（推理/规划/生成），便宜模型做「看」（分类/摘要/路由）。
- 分档看两维：任务难度 + 错误代价。
- 高代价低难度 → 便宜模型 + 贵模型评审兜底。

## 自测题

1. 一个 10 步的 Agent 任务，为什么实际成本远高于「一次对话」？列出三个放大器。
2. 预算告警为什么要分「逼近告警」和「超限熔断」两级？只有一级会怎样？
3. 缓存命中率为什么必须按 token 算、不能按次数算？命中率 50% 等于省钱 50% 吗？
4. 什么信号说明「稳定前缀被人改坏了」？怎么第一时间发现它？
5. 「分类、意图识别、摘要」这类活，凭什么敢交给便宜模型？什么情况下不能省？

## 参考答案要点

1. 因为每步都全量重发历史（输入平方增长）、工具返回回填后被反复计费、失败重试让前面的 token 白花；多 Agent 还各自独立上下文，总成本 3–10 倍（C16-2）。
2. 逼近告警让你「早发现趋势」不断流，超限熔断让你「绝对不超」。只有一级：要么来不及反应（超了才喊），要么频繁误杀正常任务（一碰就停）。
3. 按次数会把「只命中 10 个 token」也算一次命中，自欺欺人；按 token 才能反映真实省钱比例。命中率 50% 不等于省钱 50%——命中部分只打 1 折，实际只省约 45%。
4. 命中率突然暴跌（24h 内掉 30 个百分点）几乎必然是 system prompt / 工具定义 / 历史处理逻辑被改动了。用「命中率时间序列 + 跌幅告警」第一时间发现。
5. 因为这类活是「看」不是「想」，便宜模型足以胜任，且用 C20 评测集验证过达标。当「错误代价高」时不能省——分类错了影响小，但若下游直接据此发结论，就要「便宜模型 + 贵模型评审兜底」或干脆上贵模型。
