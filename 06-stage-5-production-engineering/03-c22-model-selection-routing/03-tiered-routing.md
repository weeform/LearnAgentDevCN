# C22-3 · 分级路由
> 阅读约 12 分钟。目标：学会把「什么活派给什么模型」落成一条可运行的分级路由规则，含失败升级与成本控制。

## 1. 什么活派给什么模型

模型分级（C21-4 已经埋了伏笔：贵模型做难活，便宜模型做简单活）落到选型上，就是一张「任务 → 模型」的对照表：

| 任务类型 | 例子 | 派给 |
|---|---|---|
| 分类 / 意图识别 | 「这条消息是想退款还是投诉」 | 便宜模型 |
| 摘要 / 改写 | 「把这段压缩成三句话」 | 便宜模型 |
| 路由判断 | 「这个请求该走哪个工具」 | 便宜模型 |
| 常规生成 | 写邮件、写回复 | 中档模型 |
| 复杂推理 / 多步规划 | 分析报表、写代码、数学 | 旗舰模型 |

> 核心原则：**越是「前置、高频、简单」的活，越要用便宜模型**。因为它会被调用无数次，单价差在这里被放大得最狠。

## 2. 路由的判断信号

怎么在运行时决定派给谁？四个信号：

1. **任务类型**：先从用户输入里判断「这是哪类活」（这本身就用便宜模型做一次轻量分类）。
2. **复杂度预估**：输入长度、是否涉及多步推理、是否需要工具链。
3. **token 预算**：预估这次任务要多少 token，超预算的走贵模型（或干脆拦下来）。
4. **置信度**：便宜模型给出的答案如果自带低置信，就升级。

> 判断信号要在「调用模型之前」拿到，所以只能靠廉价的启发式 + 一次轻量分类，不能为了路由再花一笔大钱。

## 3. 失败升级机制

分级路由的灵魂不是「第一次就派对」，而是**派错了能兜住**：

> 便宜模型搞不定 → 自动升级到贵模型重试，而不是直接失败。

升级的触发条件：

- 便宜模型的输出被校验器判为不合格（格式错、逻辑错、置信度低）。
- 便宜模型主动说「我不会 / 需要更强能力」。
- 任务本身被预判为高危（涉及资金、权限），直接走贵模型，不赌便宜模型。

升级要设**上限**：最多升一级或两级，到头了就交人工（呼应 C23 的人在回路），否则会陷入「无限加钱重试」。

## 4. 路由本身要便宜

路由是「每个任务必经的入口」，它自己如果很贵，就成了瓶颈——这个道理在 C16 的路由模式里就讲过：**路由判断要便宜**。

> 一个反例：为了省 1 分钱，先花 5 分钱让旗舰模型做路由判断。这叫「路由比活还贵」。

所以路由判断只用便宜模型（或纯规则/关键词），一次路由判断的 token 控制在几十个以内。

## 5. 一个最小实现

```python
# 分级路由的最小骨架：便宜模型先上，搞不定升级
ROUTES = {
    "classify":  {"model": "cheap",    "max_retry": 1},
    "summarize": {"model": "cheap",    "max_retry": 1},
    "generate":  {"model": "mid",      "max_retry": 1},
    "reason":    {"model": "flagship", "max_retry": 0},  # 难活直接旗舰
}

def route_and_run(task_type: str, prompt: str):
    tier = ROUTES[task_type]
    for _ in range(tier["max_retry"] + 1):
        result = call_model(tier["model"], prompt)
        if is_good(result):            # 校验器：格式/逻辑/置信度
            return result
        tier = upgrade(tier)           # 便宜 → 中 → 旗舰
    return handoff_to_human(prompt)    # 到顶交人工
```

关键点都在 `is_good`（校验器）和 `upgrade`（升级规则）两个函数里：校验器决定「什么算不合格」，升级规则决定「往哪升、升几次」。

> 校验器可以很简单：格式对不对、有没有踩到禁止词、置信度阈值。不必上另一个大模型——又是一笔钱。

## 6. 路由策略的账怎么算

分级路由省不省钱，取决于「便宜模型的成功率」：

> 若便宜模型能吃掉 80% 的任务、失败才升级，总成本 ≈ 80% × 便宜价 + 20% × 贵价，通常比「全用旗舰」省一个量级。

但有一个陷阱：**升级重试会让失败任务付两遍钱**。所以便宜模型的通过率越高，这套越划算；如果便宜模型通过率不到一半，不如直接上中档。

## 小结

- 前置、高频、简单的活（分类/摘要/路由）用便宜模型；推理/生成用贵模型。
- 四个路由信号：任务类型、复杂度、token 预算、置信度。
- 失败升级是灵魂：便宜搞不定自动升贵，设上限，到顶交人工。
- 路由本身必须便宜，否则「路由比活还贵」。
- 便宜模型通过率决定这套账划不划算，低于一半不如直接上中档。
