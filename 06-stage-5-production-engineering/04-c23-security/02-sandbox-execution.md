# C23-2 · 沙箱执行
> 阅读约 12 分钟。目标：理解代码执行为什么必须沙箱，会选一种实现并做资源限制。

## 1. 一句话结论

> 让模型生成并执行代码，等于把「任意代码执行权」交给了模型。不隔离就是裸奔。

当 Agent 的某个工具「运行 Python / SQL / Shell」时，模型输出的代码就是**不可信输入**——无论 prompt 里怎么写「请只做计算」，都不能改变这个事实。

## 2. 为什么 `eval` 就是漏洞

呼应 C9-3 的教训：C9-3 里的 `calculate` 用了 `eval`，`eval("__import__('os').system('rm -rf /')")` 直接变成代码执行漏洞。但这只是最直白的；更隐蔽的是模型**以为在算数，实际生成了恶意表达式**——不是有人攻击它，是它自己写岔了，照样能删文件、发请求、读密钥。

> 结论：不是「换掉 eval 就安全了」，而是「整个执行环境都要隔离」。eval 是导火索，沙箱才是防火墙。

## 3. 三种沙箱实现

| 方式 | 隔离强度 | 成本 | 适合 |
|---|---|---|---|
| Docker / 容器 | 高 | 中 | 生产、要跑任意语言 |
| 受限解释器 | 中 | 低 | 只跑 Python、快速原型 |
| WebAssembly | 高 | 中 | 跨语言、可移植、前端也能跑 |

**受限解释器**：C9-3 已经给过 `ast` 白名单版 `safe_calc`。它管住了「算数」，但管不住 `open('/etc/passwd')`、`import os`、网络请求。所以受限解释器只适合「只做纯计算、绝不碰 IO」的场景。

**Docker 容器**：给代码一个最小化的独立环境，文件系统、网络、进程、资源全部隔离。生产里最常用的方案。

**WebAssembly**：把代码编译进一个受限的沙箱运行时，隔离强度接近容器，还天然跨平台、启动快，前端也能跑同一套沙箱。

## 4. 逃逸风险与防护

沙箱逃逸 = 代码突破隔离层，摸到宿主。多数逃逸**不是「绕过了解释器」，而是「沙箱配置太松」**：

1. 挂载了整个宿主目录——读得到 `/etc` 和密钥文件。
2. 忘了断网——能内网探测、外发数据。
3. 环境变量里带了密钥——`os.environ` 一读就有。
4. 用 root 跑——配合其他漏洞直接提权。

防护四招：

- **最小文件系统**：只挂必要目录，宿主目录默认不可见。
- **断网或白名单网络**：默认 `--network none`。
- **不注入密钥**：沙箱里不放任何环境变量密钥。
- **降权 + 限制系统调用**：不用 root，加 seccomp / capabilities。

> 经验值：先收紧配置，再谈高级防护。挂载、网络、权限、密钥这四个口子不堵，再贵的沙箱也是漏的。

## 5. 资源限制：CPU / 内存 / 网络 / 超时

沙箱不只是「隔离」，更是「限资源」。模型生成的代码可能是死循环、递归爆栈、疯狂分配内存——不限制，一条代码就能拖垮宿主。

| 资源 | 手段 |
|---|---|
| CPU | cgroup / `--cpus` 限核数 |
| 内存 | cgroup / `--memory` |
| 网络 | 断网或白名单 |
| 超时 | 硬超时 kill，防死循环 |

```python
import subprocess

def run_in_sandbox(code: str, timeout: int = 10):
    try:
        r = subprocess.run(
            ["docker", "run", "--rm", "--network", "none",
             "--memory", "256m", "--cpus", "1",
             "sandbox-python", "python", "-c", code],
            capture_output=True, timeout=timeout)
        return r.stdout.decode()
    except subprocess.TimeoutExpired:
        return {"error": "执行超时，已终止"}
```

> 教学示例，生产里建议用 Docker SDK 或现成沙箱服务，而不是手拼 `subprocess`。关键是理解四个限制维度一个都不能少。

## 6. 小结

- 模型生成代码 = 不可信输入，默认隔离运行。
- `eval` 是漏洞，但换掉 `eval` 不够，整个环境要隔离。
- 三种沙箱：Docker（高隔离）/ 受限解释器（轻）/ WASM（跨语言），按场景选。
- 逃逸多因配置松：先堵挂载、网络、密钥、root 四个口子。
- 沙箱还要限资源：CPU / 内存 / 网络 / 超时，缺一不可。
