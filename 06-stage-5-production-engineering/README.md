# 阶段 5 · 工程化（观测 / 评测 / 成本 / 安全）
**层级**：阶段（阶段 5 共 5 门课）
**规模**：5 门课 / 23 篇正文（另含 5 篇课程索引）
**时长**：约 4.5–6 小时（含动手时间）
**前置**：阶段 2（5.1 可观测性建议提前到这里）、阶段 3、阶段 4
**产出**：全链路 trace + 一个回归评测集 + 成本看板 + 一套模型选型与路由策略

## 这个阶段解决什么问题

前四个阶段解决「能不能跑通」，这一阶段解决「能不能上线、能不能长期维护」。

Agent 工程化最难的地方在于：**它不是一个确定性程序**。改一个 prompt、换一个模型、调一个参数，效果可能变好也可能变坏，而且你往往说不清为什么。所以这一阶段的主线是建立「可观测 → 可评测 → 可控制」的闭环：

- **看不见**（没有 trace）就不知道问题出在哪一步
- **测不了**（没有评测集）就不知道改动是变好还是变坏
- **控不住**（没有预算和权限）就不敢让它碰真实数据

## 学完你能做到

1. 设计 trace 结构：一次任务的每一步、每个工具调用、每次重试都能回看。
2. 搭一个离线评测集，能用 LLM-as-judge 做自动打分，且知道 judge 本身的偏差。
3. 建立成本模型与预算告警，能做模型分级（贵模型做难活，便宜模型做简单活）。
4. 设计权限边界：最小权限、沙箱执行、敏感操作人工确认。
5. 为不同子任务做模型选型与路由：说清选型的四个维度，并设计分级路由规则。

## 推荐阅读顺序

1. **C19**— 先有 trace，后面评测、成本、安全的改进才能「被看见、被量化」。没有 trace 一切都白搭。
2. **C20**— 有了观测，再建评测集：改动能被自动对比，而不是靠感觉。
3. **C21 → C22**— 成本工程与模型选型是一对：先会算钱（C21），再会「按钱和活选模型」（C22）。
4. **C23**— 安全最后压轴：权限、沙箱、人工确认，是让 Agent 敢碰真实数据的门槛。

> 原大纲 5.4「稳定性：超时、限流、重试、幂等」的**单次调用层**已在阶段 0 的 C5 完整覆盖；本阶段只补**系统层**（长时任务超时、幂等键、部分失败补偿），并入 C23 第 4 篇，不单独成篇。

## 阶段出口标准

做完这四件事才算过：

1. **全链路 trace**：能回看任意一次任务的完整步骤、耗时与成本。
2. **回归评测集**：至少 30 条用例，改动 prompt 或模型后能一键跑出对比结果。
3. **成本看板**：能回答「昨天花了多少」「哪个任务最贵」「缓存命中率多少」。
4. **权限清单**：每个工具的权限级别、哪些操作必须人工确认。
