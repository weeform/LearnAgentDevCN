# C24-2 · 系统设计
> 阅读约 12 分钟，建议在电脑前边读边做。目标：把 C24-1 的验收标准翻译成架构——两段怎么分工、检索链怎么接、引用 id 和拒答阈值怎么设计。

## 1. 两段式架构：离线索引 + 在线问答

先把系统劈成两半，它们的时间属性完全不同：

| 段 | 干什么 | 什么时候跑 | 贵不贵 |
|---|---|---|---|
| **离线索引** | 读文档 → 切分 → embedding → 写向量库 | 文档更新时，一次性 | 一次性成本 |
| **在线问答** | 提问 → embedding → 检索 → 重排 → 生成（带引用） | 每次提问 | 每次都要花钱 |

> 这个切分的价值：**在线问答的延迟和成本，和知识库多大无关，只和「每次捞多少 chunk」有关**。索引再大，在线只取 top 几十条。

## 2. 切分：边界贴语义，别切碎

切分是本项目第一个难点（见 C14-2）。核心原则一句话：

> **块的边界要和「一个完整意思」的边界重合，而不是和字符数对齐。**

针对你自己的文档，用「结构 + 段落」组合切：

1. 先按标题层级切大块（`#`/`##`/`###` 是天然的语义边界）。
2. 大块内再按段落切到合适大小，目标 300–800 token。
3. 相邻块之间留 10–20% 的重叠（overlap），防止一个意思被劈在边界上。

> 反直觉事实：**切碎不是错，切「错位」才是**。500 token 一块没毛病，把「退款周期 7 天」这半句和下半句劈进两块，才是召回和引用双失败的根因。

## 3. 检索链：混合检索 + 重排

纯向量检索不够，这是 C14-3 的结论，直接复用：

1. **向量检索** top 50 + **关键词检索（BM25）** top 50，各跑一遍。
2. 用 **RRF（Reciprocal Rank Fusion）** 合并去重——两边都排得靠前的会自然浮上来，而不是简单拼一起。
3. 交给 **rerank（交叉编码器）** 只对合并后的 top 50 重排，取最终 top 5–10（见 C14-4）。

```
提问 → embedding → [向量检索 top50] ─┐
        └→ 分词 → [BM25 检索 top50] ─┴→ RRF 合并 → rerank top50 → 取 top5-10 → 生成
```

> 为什么混合检索「默认就上」：你的知识库里既有「自然语言描述」（向量擅长），又有「型号、编号、日期」（关键词擅长）。漏掉任何一类，都会直接拉低可溯源率。

## 4. 引用溯源：让 id 贯穿全链路

这是本项目的灵魂，也是「可溯源」能实现的关键。设计三条：

1. **每个 chunk 带唯一 id**：`chunk_id = f"{doc_id}:{chunk_index}"`，并且向量库里存的不只是向量，还有 chunk 原文 + id + 它在原文档里的位置（标题/章节路径）。
2. **生成时给模型编号**：把检索到的 top chunk 按 `[1] [2] [3]...` 编号，塞进 prompt。
3. **prompt 强制输出引用**：要求模型「每个事实性断言后标注 `[编号]`，没有依据就明确说没有」。

> 引用 id 不是「生成后配上去」的装饰，而是**从切分那一刻就埋进数据里的身份**。没有 id 的 RAG，引用只能靠生成模型猜，猜错就是「编造引用」。

## 5. 拒答：阈值 + prompt 双保险

单靠 prompt 让模型「自觉拒答」不可靠，要加一道工程兜底（呼应 C24-1 第 3 节）：

1. **置信度阈值**：rerank 后，如果最高分的 chunk 都低于阈值（比如 0.3，具体用评测集校准），直接判「无相关依据」，走拒答分支，不进生成。
2. **「无据则拒」prompt**：即使进了生成，prompt 里也要写死「检索结果不足以回答时，输出『文档中没有相关信息』，不要用你的常识补」。

> 拒答阈值 `Y` 不是拍脑袋，是拿 10 条「应拒答」题校准出来的（见 C24-4）：调高误拒变多，调低编造变多，用误拒率/拒答召回率两个数字去定。

## 6. 一张设计决策表

| 决策点 | 本项目选 | 理由 |
|---|---|---|
| 切分 | 结构 + 段落，300–800 token，重叠 15% | 边界贴语义，别切碎（C14-2） |
| 检索 | 向量 + BM25 混合，RRF 合并 | 语义 + 精确都要（C14-3） |
| 重排 | 交叉编码器，只重排 top 50 | 精度换排序，成本可控（C14-4） |
| 引用 | chunk 带 id，prompt 强制编号 | 可溯源的前提 |
| 拒答 | rerank 阈值 + 无据则拒 prompt | 双保险，防编造 |

## 小结

- 离线索引 + 在线问答两段式：在线成本只和「取多少 chunk」有关，和库多大无关。
- 切分按语义边界（结构+段落），别按字符数硬切；引用 id 从切分就埋进去。
- 检索走混合 + RRF 合并 + rerank 只重排 top 50，取最终 top 5–10。
- 拒答双保险：rerank 置信度阈值兜底 + 「无据则拒」prompt。
