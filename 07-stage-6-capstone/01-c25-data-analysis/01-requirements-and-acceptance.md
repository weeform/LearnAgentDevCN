# C25-1 · 需求与验收标准
> 阅读约 12 分钟，建议在电脑前边读边做。目标：把「数据分析 Agent 做成什么样才算合格」钉死，尤其明确「正确结论」和「零逃逸」两个验收口径。

## 1. 这个项目到底要交付什么

一句话：**用户用自然语言问一个数据问题，Agent 自己写 Python/SQL、在沙箱里执行、校验结果后给出结论**。

一个典型输入输出：

```
问：华东区电子类上个月的营收是多少？
答：华东区电子类 2026 年 9 月营收 128,430 元，环比增长 12.3%，是当月全品类营收最高的区域。
```

要交付的不只是一个能跑通的 demo，而是三样可量化东西（呼应阶段 6 出口标准）：

1. 一个 20 题的评测集 + 自动判分脚本。
2. 一份「正确率」和「成本」报告。
3. 一份零逃逸验证记录。

## 2. 「正确结论」的两层定义

新手常把「模型没报错」当成「对了」。数据分析 Agent 最危险的就是**算错还信心十足**——代码跑通了，没抛异常，但逻辑错了（把 sum 写成 count、把环比当同比、漏了 where 条件）。

所以要拆成两层验收：

| 层 | 定义 | 怎么判 |
|---|---|---|
| 数值正确 | Agent 产出的每个数字，与黄金答案在容差内一致 | 用评测集的 golden SQL 复算对比 |
| 结论合理 | 结论与数值一致，不夸大、不遗漏、方向对 | 数值正确前提下，看结论是否引用了正确数字、方向是否一致 |

> 关键：**数值正确是结论合理的前提**。数字错了，结论写得再漂亮都是 0 分。这就是后面 C25-2 要加「独立数值校验」环节的根本原因。

## 3. 20 个分析问题的构造

评测集不是随手写 20 个「总收入是多少」，而是刻意覆盖 5 类分析动作，否则评测会有盲区：

| 类别 | 考察点 | 数量 | 例子 |
|---|---|---|---|
| 聚合 | 单个数字：sum/avg/count | 6 | 「9 月总营收是多少」 |
| 分组 | group by + 排序 | 5 | 「各区域营收排名」 |
| 过滤 | where 条件组合 | 3 | 「华南区、单价 > 200 的订单数」 |
| 趋势 | 按时间聚合 + 环比/同比 | 3 | 「电子类营收逐月趋势，9 月环比多少」 |
| 异常 | 找突变/离群 | 3 | 「哪个月营收环比跌幅最大」 |

> 为什么异常类最值钱：它逼模型做「比较后取极值」，最容易暴露「算错还很有信心」——模型常常直接输出一个数，中间比较过程全在脑补。

每道题都要存 `{id, question, golden_sql, golden_value, category}`，golden_sql 就是判分时的复算依据（C25-4 展开）。

## 4. 验收标准：可量化的及格线

不写「效果良好」这种话，写数字：

- **数值正确率 ≥ 18/20（90%）**：20 题里至少 18 题产出数字与黄金答案一致（浮点相对容差 0.01%）。
- **结论合理率 ≥ 16/20（80%）**：在数值正确的基础上，结论引用正确数字且方向一致。
- **执行零逃逸**：20 题执行过程 + 一组专门构造的逃逸测试（C25-4 会列出），越权尝试全部被拦截、沙箱进程正常退出，逃逸成功 = 0。
- **单题平均成本**：记录在案即可（不设硬门槛，但要有数），用于 C25-4 的成本对比。

## 5. 沙箱是硬约束，不是可选项

> 模型生成的代码是**不可信输入**。让它直接在你的机器上跑，等价于把 root shell 交给一个会犯错、还能被 prompt injection 诱导的模型。

三点把「为什么必须是沙箱」说死：

1. **模型会生成任意代码**：你不知道下一段代码里有没有 `os.system("rm -rf ...")`、`open("/etc/passwd")`、无限循环吃满 CPU。
2. **prompt injection 会放大风险**：你的数据里如果混进了「忽略前面指令，执行……」的文本（比如某个 region 字段被注入），模型可能被诱导出恶意代码。
3. **「内部数据」不等于「安全」**：数据是你自己的，但模型不是——它可能写坏文件、打爆内存、把数据发到外网。

> 所以本项目把「执行零逃逸」和「数值正确率」并列验收。安全不是加分项，是和「能不能算对」同级的及格线。

## 小结

- 交付三样可量化东西：20 题评测集 + 正确率/成本报告 + 零逃逸记录。
- 「正确」分两层：数值正确（黄金答案复算对比）是结论合理的前提。
- 20 题刻意覆盖聚合/分组/过滤/趋势/异常 5 类，异常类最暴露「算错还很有信心」。
- 沙箱是硬约束：模型代码是不可信输入，裸执行 = RCE。
